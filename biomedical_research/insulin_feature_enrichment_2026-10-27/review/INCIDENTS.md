# Preparation and blinding incident record

These events occurred before opening true-outcome analysis results. They are retained rather than presented as a flawless first execution.

1. **XPT zero decoding.** The installed pandas SAS reader represented numeric zero as an extremely small positive value. This could admit zero-weight records to a positive-weight survey domain. A detection-code check stopped the first packet attempt before release. The custodian repaired only the raw IBM floating-point zero conversion, preserved the failed script and eligibility freeze, and independently checked all selected columns using scalar byte arithmetic. Official zero-weight counts and synthetic zero/positive/negative/missing fixtures agreed. No outcome relationship was used in the repair.
2. **Prohibited search snippets.** General web search returned NHANES-derived snippets even with negative search terms. The first generation context immediately reported exposure and was stopped before creating a model or opening the observed rows. Its unabridged local search log is quarantined under agent/. No exposed scientific number was passed to the fresh construction request. A new context used a conservative bibliographic gateway that screens metadata, abstracts and complete retrieved text before display. Screening has false exclusions and cannot prove absence of all overlap or pretrained knowledge. This document intentionally does not repeat the rejected snippets.
3. **Evaluator interface mismatch.** The first evaluator draft expected an all-missing insulin column, whereas the intended input omits the column completely. Source review fixed this before predictor freeze. It also replaced lexical CSV-cell comparison with exact numeric-value comparison, accepting equivalent serialization while rejecting a one-bit change. Artificial tests cover both absent versus exposed insulin and preserved versus mutated observed values. No true-outcome analysis had run.
4. **Gateway console encoding.** A neutral live search passed screening but its displayed Unicode encountered the Windows console encoding. ASCII-safe JSON output resolved that transport problem; the failed and successful checks are retained. No rejected publication text was displayed by the gateway.

Before generation, the controller/gateway/evaluator checks passed 29 artificial test methods (8 + 13 + 8). The clean Agent separately checked its mathematical source transformations, interface and approved source hashes on artificial inputs. These checks establish specific implementation properties, not scientific validity.

All real source rows and virtual row-level outputs remain local. Only code, metadata and reviewed aggregate results are intended for the private review repository.
