# 当前实际系统架构核查

核查日期：2026-11-11。范围是两个已经完成、分别冻结的运行版本：`request_only_repeatability_2026-11-11` 的自主构造，以及 `scientific_check_revision_2026-11-11` 的成对复查。本次仅阅读协议、控制器、工具实现和已保存汇总，制作说明图；未调用模型、生成数据、读取患者行或重新拟合分析。

**一句话：每个会话是一个 GPT 科研 Agent，自己检索证据、选择模型结构和参数并写出生成器；确定性工具执行检索、隔离抽样和检查；Agent 决定保留或改写；全部会话结束后，另一条评估路径比较生成数据的科学分析结果。**

这不是“20 个 Agent 协作生成一张表”，也不是主程序预先写好生物学关系后让 Agent 填参数。多次构造、两种策略和新上下文复查，是实验重复与比较。最多两个会话并行是运行调度，不是协作机制。

## 1. 当前输入和科学决策

自主构造输入为目标人群、变量名称、单位、所需分析以及输出格式。两个当前案例均为**没有目标个体输入的完整虚拟人群生成**；`generate(observed, spec, seed)` 接口中的 `observed=None`。总体研究保留增补未测指标与缺失值补全，但不能把这次整个人群实验写成已经同时验证了所有模式。

Agent 可以决定：搜索什么、读哪些来源、采用哪个统计关系、怎样换算单位或组合证据、使用什么分布和条件结构、哪些参数只能假设、是否试运行、是否修改以及何时终止。宿主定义任务、可用工具、预算、输出契约和评估计划，没有在这些会话中代填目标斜率、相关、标准差或期望符号。提示里的流程组织与科学模型本身需要区分。

## 2. API 和工具循环已经实际接通

`api_loop.py` 调用 GPT Responses API，冻结模型为 `gpt-6.1-sol`、high reasoning、default tier。请求采用 `tool_choice=auto`、`parallel_tool_calls=false`、`store=false`。Agent 返回函数调用，控制器验证工具名和 JSON 参数、记下调用意图，派发工具，再把工具输出加入下一次上下文。调用、模型身份、提示、返回内容、使用量和费用估算均留存；内部推理不被当作公开可解释性证据。

控制器管理预算、恢复和版本绑定，不负责科学模型搜索。它保存工具返回而非重新派发不确定的副作用；异常、预算耗尽、无最终选择与失败均是可记录结果，不能偷偷用某个候选充当 Agent 的最终输出。

定位：`request_only_repeatability.../api_loop.py:297`（请求配置）、`:399`（调用往返与留痕）。

## 3. 文献工具是有范围的自主检索

`literature_search` 通过 Europe PMC 获取来源卡片；`read_source` 可分页读取缓存元数据、摘要、PMC 原文分节和表格；`list_sources` 显示当前来源目录。当前不是任意网站浏览器，也不应写成可自由访问所有医院网站、付费全文或任何附件。缓存保留来源标识、版本与哈希；同一来源多个版本需要明确处理。

自主构造的普通 Agent 与 workflow 均从研究需求出发，没有先给准备好的证据包。成对复查则有意给双方同一份原始需求、冻结生成器和此前捕获的原文目录，并允许追加检索；这是“审查既有模型”的隔离实验，不能混写成新的端到端检索对照。

目标家族别名筛查是防护而非绝对隔离证明，旧来源预览暴露仍保留在登记中。可追溯表示能查原文与版本，不表示引用一定抽取正确或适用于目标人群。

## 4. 数据究竟怎样生成

`submit_candidate` 保存 Agent 写的 `generator.py`、原样传递的 `model_spec.json` 以及说明/依据。每次提交是新版本，提交后不可原地修改。机械检查不执行程序，也不认证科学正确性。

`run_candidate` 才启动隔离执行。当前工具运行器的 `isolated_run` 自己准备任务、模型、代码和固定种子，调用 `cohort_harness.execution` 的运行时、命令和捕获辅助函数，再由 `cohort_harness/_worker.py` 在 WSL/bubblewrap 中调用 `generate(observed, spec, seed)`。因此不能简单声称本次直接调用了通用的 `execution.run_candidate` 入口。工作进程无网络、不挂载患者参照或凭据；失败不会回退到主机导入执行 Agent 代码。

**Agent 决定随机生成规律，程序依照这个规律抽样出表。当前主要实验证据是程序生成路线，不是 GPT 在答案中逐行直接输出患者记录。** 同一生成器能按指定种子重复采样，并不增加新的临床样本或消除模型假设。

定位：当前 `tools_runtime.py:349`（提交）、`:383`（试运行）、`:434`（生成后统计）、`:470`（隔离执行）；`cohort_harness/_worker.py:13`。

## 5. 检查分两层，不能混同

| 已接通的路径 | 实际计算/检查 | 能说明与不能说明 |
|---|---|---|
| 初始自主构造 | 字段/输出契约，隔离运行状态；从保存生成表计算分布、请求回归和残差相关 | 告诉 Agent 自己生成了什么；不是与目标答案对照，也不是在来源人群中重放文献统计 |
| 后续成对复查 `inspect_law` | 静态数学警示、作者的支持域/矩声明；作者声明的线性生理规则及计数；联合关系的参数来历、调整集、依赖和不确定性声明；同一生成表的数值分析 | 检查绑定具体候选与具体试运行。AST 警示不是证明；生理规则由 Agent 声明，不自动成为普遍真理；来源注册/声明覆盖不认证原文抽取或迁移 |

后续复查普通与结构化两组都能用同一检查工具。结构化组额外要求选定版本覆盖数学变量及请求分析，明确写出无法判断也可以；不是必须宣称通过。`inspect_law` 可复用已校验哈希的隔离试运行，或者在预算内运行一次；返回的是生成数据统计，永不附带目标相关或“正确修复值”。

当前数值分析器按预定血压/血脂请求派发固定回归和依赖算子；“Agent 自选生成模型”不等于“系统已自动支持任何新的分析算子”。研究问题可以显式提供给 Agent，但扩展到新指标与新分析仍需要事先定义单位、格式及可信分析实现。

该路径的接口为 `review_schema` / `inspect_law`；实现为新版本 `tools_runtime.py:193` 和 `law_checks.py:126,424,446`。它**没有把早期 `semantic_feedback_v1`、`source_replay_v2`、`conditional_feedback_v1`、历史校准优化器或完整 adaptive session 组件作为本轮主入口调用**。这些模块存在于仓库，不等于本轮使用了它们。

## 6. 修订是选择，不是自动优化或已证明收益

Agent 可以补读来源、试运行、提交新候选、保留原稿或者报告不能完成。`finalize` 选择一个具体不可变版本。初始自主构造实际为 12 个候选、12 次成功试运行，均选择 v001；不能把“支持修订”写成这一轮发生过多次优化。

后续复查为同样 12 个起始模型各两次新会话，共 24 次：20 次明确保留，4 次改代码；其中仅一对起始模型的最终数值表改变。检查发现并修复特定缺陷具有实际用途，但结果没有证明结构化复查普遍提高科学分析质量。图中的虚线表示可选保留/改写决策，不表示必然改善。

## 7. 冻结、分析和独立复算

全部构造/复查会话结束并记录最终版本后，`evaluate_pilot.py close` 绑定输出与哈希，`draw` 执行预定三个种子，`evaluate` 才读取已固定的真实样本参考汇总。当前自主构造 12 个模型产生 36 个最终表；复查 24 个分支产生 72 个表。这些是两个实验，不是 108 个独立生物医学案例。

对生成表运行请求回归、残差相关与分布分析，然后与已有真实样本参考比较；独立数值审核从保存表重新计算。独立复算指算法/执行复核，不等于已经完成外部医生审查。当前参照此前已揭示，是开发性比较而非新保留队列；真实样本估计也不是已知总体真值。参考不确定性只采用实际已有的区间，不能捏造相关系数置信区间。

“可解释、可追溯”的可支持表述是：原文、参数说明、模型代码、检查声明、采样文件与最终估计之间可以追查。尚未证明自动生成的可信度标签能预测误差，也不能据此宣称全部科学结论可信。
