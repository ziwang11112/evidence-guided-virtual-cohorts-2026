11 November 2026. New, bounded execution unit following the user's instruction to continue the v0.29 extension plan. The completed R0/R1/R2 pilot units and v0.29 manuscript remain unchanged. This is a twelve-constructor repeatability experiment under the current working scientific inputs, not reopening earlier failures or retuning an exposed reference.

## Question, scientific freedom and common information

Can the current Agent procedure repeatedly transform the same biomedical research request into a complete virtual cohort that supports its specified scientific analyses? Compare ordinary Agent and workflow descriptively, including delivery, analysis-specific results, source use and cost. Workflow superiority and feedback improvement are not requirements for useful generated data.

Both arms begin with the exact same case request, eligibility, schema, units, requested analyses and mechanical tools. Both start with no prepared source papers, coefficients, old programs, target results or desired signs. Both may independently search, inspect sources, choose a scientific structure and parameters, write a generator, check generated-only analyses, revise and finalize or declare inability. The ordinary Agent is a capable tool-using coding Agent, not a single-turn or no-search strawman. The workflow differs only by its reusable scientific organization instructions. Scientific policies, common instructions, requests, contracts and tools_runtime.py are byte-identical to the completed current-capacity pilot; their hashes are in UNCHANGED_SCIENTIFIC_INPUTS.json.

Human tasks are defining the request and evaluators, operating and auditing the infrastructure, and interpreting results. The host never fills a missing biological parameter, changes an Agent law, suggests a desired sign, selects an unfinalized candidate, or supplies a known reference answer. Final tables are program-route samples from Agent-authored immutable laws. Ordinary Agents may spontaneously apply practices similar to the workflow. No multi-Agent mechanism, training or automatic scientific optimization is introduced.

## Execution and retrieval boundary

The common tool runtime remains unchanged. Europe PMC search and screened available PMC full text/tables are accessible through recorded episode-local sources. Retrieval is agent-directed within this source service, not unrestricted web search. Multiple source versions require explicit selection. Screening excludes known target-family aliases and project identifiers before display but is not proof of independent sources or absent model prior knowledge. An incidental exposure discovered in audit is recorded and never fixed by replacing the author. Source retrieval and extraction are distinct from statistical correctness and transportability.

Programs implement generate(observed,spec,seed), with observed=None for these whole-cohort tasks. spec passes through exactly as submitted; task metadata is separate. Only the existing WSL/bubblewrap isolated worker executes candidate code. No host filesystem/reference/credential/network access or native fallback. Submission freezes an immutable candidate, execution returns actual saved-output statistics, and finalize selects an exact immutable version. Generated-task diagnostics are neither source-population replay nor target-quality feedback. No patient data are newly downloaded, decoded, fitted or transmitted. Clinical evaluation reads only a pinned existing host-side aggregate reference after global construction closure and final draws.

## Failure, no-op and stopping rules

Routine terminal outcomes are finalized (including declared inability), call_limit,input_byte_limit,budget_limit,action_limit, output_token_limit (explicit provider max_output_tokens exhaustion) and model_stopped_without_finalize. They remain outcomes and do not trigger replacement, extra resources, favorable seed selection or expanded paper collection. Candidate execution errors returned through an intact tool interface may be corrected by the Agent within its fixed budget. No scientific no-op is called an improvement.

Any non-routine terminal API/transport/runtime/interrupted-tool state or integrity exception blocks further fresh dispatch. An already-running companion may finish without a retry or budget extension. Root inspects the concrete operational evidence and saves a versioned decision. Undispatched planned cells are recorded as not_started_due_protocol_stop; do not invent Agent outcomes for them. Ordinary all-twelve evaluation closure remains unavailable after such an exceptional halt until an explicit documented decision. No outcome-based exclusion or replacement is permitted. The first-block gate does not certify scientific quality and cannot change scientific policy after observing outputs.
