# Can a scientific agent design a virtual cohort from a new article?

Design for review, 22 November 2026. The two development requests are ready for interface testing. The prospective article list, independent answer keys, runtime and run manifest still need to be frozen. This document reports no new generation results.

## Scientific question

A researcher supplies an article and a question about its population. Can an agent independently decide which measurements belong on each virtual record, turn the relevant published evidence into a runnable model, and deliver data that support an appropriately qualified answer? The first test covers whole cohorts with no participant input and descriptive analyses of paired measurements. A usable answer might be a point estimate supported by the source, or two admissible cohorts that give materially different answers under explicit assumptions.

The test changes who does the scientific design. The prior [iron request](../article_portfolio_2026-11-22/iron/REQUEST.txt) names fourteen evidence fields and specifies the marginal grids. The [lung request](../article_lung_pairing_2026-11-22/REQUEST.txt) explains how to reconcile rounded regression and marginal statistics. Those controls isolate pairing in the earlier study. Here the constructor receives only the [short research request](development_requests.json), the original paper and any prespecified public supplements.

## What the coordinating agent decides

| Step | Agent decision | Observable output |
|---|---|---|
| Define the analysis | Identify the population, sampling unit, measurements, transformations, subgroup weights and requested statistic. Resolve definitions against the paper. | A machine-readable task and the analysis to run on produced rows. |
| Read the evidence | Choose the relevant tables and text. Recover units, adjustment, conditioning, precision and denominators. Distinguish a direct report from a derivation and a modeling assumption. | Each material constraint links to a source location and specifies how to recompute it. A derivation records its inputs. An assumption records which analysis depends on it. |
| Build the cohort | Choose marginals, joint structure, distribution family and numerical solution. Decide when another reading, trial or model is useful. | An immutable generator, analysis inputs, seeds and source checks. |
| Answer the request | Decide whether the data support a point conclusion, demonstrate sensitivity, or cannot support the requested use within the available evidence and tools. | A virtual table or labelled scenarios when feasible, the estimate for each requested use, and a reason for its interpretation. |

The shared vocabulary covers measurement, population, unit, statistic, conditioning or adjustment, source location and assumption. New biomedical variables are data in that vocabulary. Disease-specific field lists, table numbers, marginal families and pairing rules belong to the agent's submission. Independent evaluators retain responsibility for scientific grading. The agent can correct its own submissions within its fixed budget and cannot change the research question or grading rule.

## What needs to change in the runtime

The [request runtime](../request_only_repeatability_2026-11-11/tools_runtime.py) already supports paper retrieval and reading, candidate submission, isolated trials and finalization. Its constructor expects a validated task. The [original-paper runtime](../original_paper_capability_2026-11-17/tools_runtime.py) dispatches scientific summaries by registered case. Add one article-reader stage before task validation. It receives an opaque run ID, normalized paper and the research question. It passes the agent-authored task into a case-neutral executor. Give both experimental arms the same source-reading, numerical and execution tools.

Reuse the [evidence validator](../../cohort_harness/analysis_evidence.py) for structure and [source operators](../../cohort_harness/source_checks.py) where their mathematical definitions match. The current operator set includes means, dispersion, quantiles, correlations, OLS coefficients and proportions. Before evaluating these two development articles, test general operations for contingency-table odds ratios, derived-variable thresholds and ratios of standardized means. Declare the supported operations at freeze. An unsupported operation on a registered article is a recorded outcome. No per-article fallback or post-freeze patch counts toward unassisted completion.

## Development, then a prospective pilot

1. Use the two exposed development papers to check the full path from request to table to independent analysis. Test the evaluator with one mathematically equivalent correct derivation and two deliberately wrong submissions, one substituting an adjusted odds ratio for the crude one and one applying a unit change without scaling the values. Confirm that the correct alternative passes and the two mistakes are detected. These are implementation checks.
2. For a small pilot, register four new articles from distinct studies on at least two measurement domains. Use a dated search and an ordered eligibility list. Include successive eligible articles with accessible full materials, an interpretable population and paired measurements relevant to a descriptive request. Record every exclusion. Select without inspecting target microdata effects or agent performance. Previously used papers and cohort overlaps are recorded and excluded from the new-article count. A new article here means held out from project development. Public papers may be known to the underlying model.
3. Fix one research request per article, source corpus, paper version, meaningful differences for the requested use, rounding and Monte Carlo tolerances, operator versions, sample size, evaluation seeds, model snapshot, and maximum calls, tokens, executions and spend before either arm starts. Define study-specific scientific tolerances in their natural units with independent reviewers. Both arms may navigate the entire permitted corpus. Testing open-web study discovery is a separate question.
4. Pair an ordinary agent and the coordinating workflow on each article. Both start fresh, receive identical material, use the same GPT, generic submission interface and numerical backend, and can retry within identical limits. The workflow requires an explicit, revisable evidence-to-analysis map before finalizing the model. The ordinary agent can organize its work freely. Randomize order within article. Use one registered primary session per arm and article. Repeated seeds test a submission's numerical stability. This contrast estimates the value of the workflow as a whole. A claim about the ontology alone would need its own ablation.

## Independent scoring and decision

Before authoring, have two independent readers identify analysis-critical source facts, acceptable equivalent derivations, material semantic errors, applicable tolerances and relations the source leaves open. Resolve disagreements and lock their key and estimator away from the constructor. Use the paper as the only case-specific source of hints supplied by the system. Keep author conversations, task adapters, prior runs and project repository out of its context and tool paths. At scoring time conceal arm labels. Rerun the registered analysis on delivered rows. Give each constraint credit for substantively correct interpretations, including equivalent formulas and units. Record missing constraints as well as erroneous additions.

**Primary endpoint.** For each arm report the number of registered articles completed without case-specific author help and passing scientific review, divided by all registered articles. Passing requires a runnable cohort, independently reproducible requested analyses, adherence to all analysis-critical source constraints, and a defensible account of which conclusions rely on assumptions. A sensitivity answer can pass when distinct, source-compatible tables produce a material difference under defensible stated assumptions. Two examples support an attainable contrast. A claim of a sharp bound needs a separate argument. Report justified abstention, unjustified refusal, unsupported operations, incorrect conclusions, timeouts and human rescues separately. None earns a completed cohort. Log all automatic retries, manual interventions, actual calls and cost.

**Decision.** Advance to the four articles only after both developmental paths execute end to end without hidden case adapters and the evaluator accepts the correct controls and rejects the errors. Use the pilot to locate the first consequential failure per article. Compare the two arms by article and publish all paired outcomes. If both succeed similarly, report unassisted feasibility and retain the simpler implementation. If the workflow fixes an error, trace the exact evidence decision and its effect on the scientific answer. If the common executor fails, fix it in a new version and keep the original result. Four articles support a feasibility assessment. Stronger claims about workflow advantage need a larger independent sample. Generalization to a new patient population additionally needs an independent measured reference and its uncertainty.
