# Lifestyle application runtime adapter

11 November 2026. Preparation only: no API request, credential read, generator execution, new source download, or target calculation was made by this runtime subtask.

## Reused and changed components

The old repeatability launcher's durable transport, byte-based reservations, cost reconciliation, response/model identity checks, complete private request/response captures, function-call correspondence, interruption behavior, OS locks and two-active-session cap are reused by module import. A new unit-local adapter replaces only its registered scientific matrix, input assembly and launch/dispatch gates. It supports `LIFESTYLE_A1` and `LIFESTYLE_A2`, fresh contexts, gpt-6.1-sol/high/default, at most 4 USD per constructor and 8 USD overall. The root's frozen plan may tighten any ceiling.

The old `tools_runtime.py` automatically detects PNS versus lipids and loads old endpoints. That path is not used. The new runtime retains retrieval, source journals, immutable submissions, generated-only trials and terminal finalization, but calls only `analysis_operator.generated_diagnostics(frame, task)`. Missing or invalid diagnostics fail explicitly. The analysis function must state `target_reference_read: false` and must not load real-reference data. No relationship, desired direction, generator family or scientific numerical parameter is present in this adapter.

Execution preserves the existing WSL/bubblewrap staging, worker, limits and hash receipts. There is no host import/execution of submitted Agent code and no fallback to unrestricted Python. Final output generation requires all registered constructors to close and the selected immutable law to be bound. Three final seeds per constructor are separate from Agent-visible trial seeds. Failure and unavailable slots remain in the final manifest; interrupted actions are not silently retried.

The user-approved source paper is legitimate input for this source-rich reconstruction setting. `PLAN.json` supplies a nonempty `evidence_paths` list; UTF-8 artifacts are inserted verbatim as untrusted evidence in the initial user content, with their names and all bytes bound by the launch freeze. Task `excluded_cohorts` must not forbid Turkana in this unit; retaining project aliases is compatible with the existing gateway's nonempty-exclusion requirement. The Agent can also search/read through the existing Europe PMC gateway within root-selected budgets.

## Root-provided files and interfaces

- `PLAN.json`: `model`, `limits`, `episodes`, `common_instructions_path`, `evidence_paths`, and `evaluation_seeds`. Episode fields: `episode_id`, `case_id: lifestyle`, `arm: workflow`, `task_path`, `request_path`, `policy_path`.
- Task schema and scientific prompt: root/source team defines population, variables, group codes, measurements, intended analyses and allowed evidence. Author chooses structure and parameters.
- `analysis_operator.py`: `generated_diagnostics(frame, task)` returning a finite JSON object with `target_reference_read: false`. The same scientific operator should be callable by the later real/virtual evaluator. This module is root-owned and independently reviewed before launch.
- `PROTOCOL.md`, source evidence, existing exact model/rate verification records, and independent `PREFLIGHT_REVIEW.json`.
- `LAUNCH_FREEZE.json`: complete required local hash map, external dependencies and credential-helper hash; `ROOT_EXECUTION_APPROVAL.json` binds it. No existing approval is reused as if it belonged to the new scientific unit.

Use `api_loop.required_local_files(plan)` and `api_loop.required_external_files()` when assembling the freeze. Bind the legacy key-loader's Python file hash, not the contents of D:/.env. The legacy loop reads credentials only after both live gates pass. Secret values are never printed, copied into model inputs or exported.

The accepted limits are compatible with: 48 calls, 60 actions, 20 provider queries, 16 downloads, two immutable submissions and two diagnostic executions (initial plus at most one revision, including failed execution attempts), trial seed 63001, final seeds 64001/64003/64007. The protocol decides the exact settings; these are not model parameters.
