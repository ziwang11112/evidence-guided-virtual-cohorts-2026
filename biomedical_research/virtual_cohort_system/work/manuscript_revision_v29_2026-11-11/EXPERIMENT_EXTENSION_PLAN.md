# Focused extension plan: scientific use, traceability and model robustness

Design only, 11 November 2026. No API calls, new cohorts, patient reads, model launches, contacts or paid runs are initiated by this plan. The completed request-only continuation remains closed. Any next execution gets a new frozen protocol, budget and complete attempt ledger; old frozen generators and results remain unchanged.

## Priority decision

Keep final virtual data and its scientific analyses central. Strengthen three connected questions: **Does the current request-to-data procedure work repeatedly? Can a reviewer inspect its scientific basis efficiently? How much does the answer depend on the model configuration?** Do not make workflow superiority, feedback gains or a calibrated confidence card prerequisites for a useful application paper.

The next experimental unit should be a modest repeat of the repaired current procedure, not another interface or source-curation redesign. In parallel, a traceability audit can reuse completed artifacts without generating another row. After that matrix, adding one existing glycemia request under the unchanged runtime may strengthen scientific breadth more than adding another model. These answer different questions and are alternatives to prioritize, not instructions to run every combination. Different-provider breadth is optional; the user's latest economical GPT-only preference remains the default.

## A. Repeatability of the current request-to-data method

**Question.** Are the latest selected analytical agreements reproducible across independent constructions under one fixed current implementation, and do ordinary Agent and workflow differ consistently in delivery, scientific results or auditability?

**Recommended bounded matrix:** two existing requests (PNS BP and Turkana-context lipids) × two policies (ordinary and workflow) × three fresh constructor sessions = **12 new sessions**, at most **36 final tables** under three fixed seeds per finalized law. This is twelve authoring opportunities on two clinical reference contexts, not thirty-six clinical validations. Preserve the old final diagnostic as pilot history; do not count its favorable output as a prospectively assigned replicate of the new matrix.

Both arms begin with the same request and no prepared papers, coefficients, old models or reference outcomes. Both receive the same search/read/execute tools, packages, output schema and common limits. The workflow's treatment is its reusable scientific organization. The ordinary Agent remains free to search for conditional evidence, derive relationships, check assumptions and revise. Different retrieved studies are part of the end-to-end result, not a fairness failure.

Freeze the actual currently working GPT model ID/returned identity, reasoning setting, common instructions, both policy texts, source service and exclusions, tool/runtime hashes, candidate selection, reference mapping and evaluation code. A catalog/compatibility check immediately before any later paid run must confirm the chosen model and then freeze its configuration. Do not silently substitute an alias, expensive fallback or another provider mid-batch.

Use the current common operational ceilings as the starting design: 48 model calls, 750,000 bytes for each serialized Responses request body (including its accumulated history, tools and instructions), 60 actions, 20 provider queries, 16 article downloads, six candidates/trials and the existing isolated worker. The byte ceiling is checked on each outgoing request, not summed across an author's session. These are maximum opportunities, not mandatory consumption. Keep the same final row count (3,000) and three predeclared evaluation seeds; authoring repetitions, not extra rows, address the present uncertainty.

**Budget proposal, not authorization to spend:** retain a $4 accounted maximum per session, with a $48 maximum for all twelve. At the last four-session average, a simple extrapolation is roughly $3.83 for twelve, but this is neither a quote nor a safe upper bound. Use durable reservations including unknown-usage calls. The user's monthly allowance is not a verified remaining balance. Review current tariffs before freezing and allow the user to choose a lower total allocation; if a smaller batch is chosen, change all planned cell counts before launch, never after seeing scientific results.

Run a complete four-cell execution block first to check only operation/accounting, then the remaining two blocks under the same frozen method. Withhold the clinical comparison dashboard until all twelve sessions are terminal, avoiding a favorable-result stopping decision. Any protocol-breaking interface failure stops further dispatch with all attempts preserved; it triggers a versioned engineering decision, not replacement of a failed cell. Normal resource exhaustion or poor scientific quality remains an outcome and does not earn extra calls.

For each finalized law, calculate every existing primary analysis and diagnostic with unchanged code. Retain delivery status as a separate endpoint. Report constructor means and all three seed estimates; seed dispersion is conditional simulation variation. Report native-unit effect differences and the reference's actual uncertainty convention. No new equivalence margin, score weight or win threshold should be selected from these known reference values. If a biomedical collaborator can justify a use-specific tolerance independently of the results, freeze it before the new evaluation and show it as a separate decision analysis.

Use plots of every constructor, with side-by-side policies within each request. With three authors per cell and only two requests, effect distributions and failures are more informative than broad superiority tests. No task-general conclusion can follow from treating six estimands or thirty-six tables as independent datasets. Record calls, elapsed time, billed-token usage, retrievals, selected source versions, human corrections and estimated cost separately.

**Decision after the complete matrix:** if both policies deliver similar useful profiles, simplify the paper's architecture claims and retain the explicit workflow for inspectability. If one policy differs consistently in a specific analysis, inspect the numerical evidence and law choices before proposing a targeted mechanism experiment. If key analyses remain scientifically unsuitable, report that boundary and stop expansion of that claim. Do not change the target or outcome merely to obtain a stronger headline.

## B. Make traceability useful, not merely decorative

**Question.** Does the provenance record help a biomedical/statistical reviewer correctly identify the basis and limitations of an analysis?

The immediate no-generation prerequisite is an audit table linking source locator, original statistic/operator, adopted value, transformation/assumption, code location and affected analysis. Use every finalized law in the latest round, not only the good BP relation. There are **four laws × three primary analyses = twelve analysis dossiers**. Some parameters support more than one analysis, so repeated links are not independent evidence. Incomplete mappings and unresolved assumptions remain marked, with the denominator defined from required analysis dependencies rather than the number of claims the Agent happened to volunteer.

Assess separate properties: link completeness, source support, semantic correctness, implementation agreement and unresolved transfer assumptions. A filled field is not a correct field. A valid reported value can still be incompatible with the target operator. Existing static provenance audits supply adjudication material, not calibrated trust labels.

**A small human usability pilot** can compare two presentations of the same frozen construction:

| Presentation | Available materials |
|---|---|
| Standard reproducibility package | Research request, executable program/specification, source access/locators and generated-analysis definitions |
| Same package plus provenance map | Exactly the same scientific content and program, with the source-to-assumption-to-code-to-analysis navigation map |

This tests the added record, not different generated datasets. Mask model/provider/policy identity and clinical-reference answers where feasible. Format cannot be blinded, so do not call this a double-blind study. Reviewers must be independent of original construction and adjudication. Two external reviewers are sufficient only for a **descriptive pilot**: each reviews twelve different dossiers, six in each format, with the other reviewer receiving the complementary format for that dossier. Counterbalance order and analysis/case; neither reviewer sees the same dossier twice. Related dossiers from the same law can still produce learning, so balance their order, record it and report this limitation. Four reviewers would permit more independent assessments but are not required to begin a qualitative check.

Before scoring, an independent source/code adjudication records accepted answers and unresolved questions without using target agreement as correctness. Questions should ask the reviewer to identify the original source statistic, unit/conditioning distinction, an unsupported bridge, the relevant implementation location and an analysis affected by the assumption. Score factual correctness with a fixed rubric, time to a correct answer, false accusations of error, confidence in answers and unresolved responses separately. Known historical audit errors must not be treated as gold truth; preserve the existing withdrawn Greiner-pointer criticism.

The principal units are dossiers nested in four laws and reviewers. With only four laws, report paired descriptive outcomes and reviewer-level results rather than a population-wide efficiency claim. Natural defects/assumptions are sufficient; artificial injected defects, if later used, must be isolated copies and explicitly identified as a controlled debugging task. Do not edit the published generator or pretend injected errors occurred during scientific generation.

If only one biomedical friend is available, ask for a qualitative usability/source-applicability review and use the feedback to improve the package. Do not present it as a comparative user study. Contacting or enrolling reviewers is not performed by this document.

This experiment can support the stronger statement "the provenance package helps reviewers inspect scientific assumptions." It cannot show that an LLM explains its hidden reasoning or that provenance predicts new-population accuracy.

If the intended paper claim is a reusable biomedical construction method, **one additional existing glycemia request may therefore be more informative than a second model configuration**.

The existing ENSANUT before/after-glucose-adjustment BMI analyses offer a distinct joint-analysis use, while CHNS offers an existing age/BMI/glucose-to-HbA1c request. These sample results are already known at project level; neither becomes a new confirmation or an outcome-blind case selection. Do not select between them using new Agent outputs or change the chosen analyses after seeing those outputs.

Readiness is **not yet certified**. Before any freeze, review the exact schema and units, eligibility/target description, all three existing estimator definitions and reference hashes, missingness policy, endpoint-output mapping, and source-exclusion aliases for the chosen clinical family. Confirm that the current generic runtime can execute that schema and that the old cached aggregate references can be used without decoding or refitting patients. No new target family, patient-data acquisition or patient analysis is needed. Agent-directed external literature retrieval remains available under the same common gateway and exclusion policy, with no curator-prepared numerical packet.

The optional matrix is **one request × two policies × three fresh constructors = six new sessions**, at most **18 final tables**. Keep the same GPT configuration, shared tools/ceilings and scientific decision freedom as A, apart from the reviewed task-specific contract and family-exclusion configuration. No historical author is imported as a new replicate. A proposed $4 per-session cap gives a maximum $24 allocation for this option; this is a design ceiling, not a spending authorization or expected bill.

If the new schema requires a scientific estimator or generator-interface change, audit that change before dispatch and version it explicitly. Do not call results from a changed runtime a clean breadth replication of an unchanged method. If readiness fails, record the reason and defer this option rather than creating another data-acquisition branch.

After A, choose this option when the principal uncertainty is **coverage of different requested scientific analyses**. Choose D instead when the paper's principal uncertainty is **dependence on the underlying GPT configuration**. Neither automatically triggers the other, and no new case/model Cartesian grid is proposed.

These captured identities describe historical receipts, not current model recommendations or newly verified availability. The roster is unbalanced; provider, model capability, adapter behavior and allowed output computation differ. The two later review branches are dependent on their parent laws and are not additional initial-model replications. Do not turn unavailable outputs into zero correlations, and do not conclude that a provider cannot perform the task because its responses were incomplete in one adapter.

The existing results already justify a supplementary **model/configuration feasibility and assumption-choice analysis**. Show delivery separately from scientific profiles among delivered laws, keep all failures and give exact configuration/usage records. Do not headline a ranked best model from these cells.

If broader live-workflow robustness is needed, add **one economical GPT configuration** after the current frozen repeatability matrix, not all four providers at once. A balanced design is two requests × two policies × two configurations × three authors = **24 sessions, at most72 final tables** total, with the first12 from A only if exactly the same protocol and evaluation remain unchanged. Otherwise run a separately versioned design and keep earlier results descriptive. The additional12 sessions would have a proposed maximum $48 under the same per-session cap; no authorization or current price is implied. Exact configuration selection waits for availability, compatibility and price verification, and must precede scientific output inspection.

A same-GPT-family comparison tests configuration dependence, not provider independence. If the paper later claims broad model portability, use at least one independently operated provider in a new balanced protocol and document adapter parity. That stronger claim is optional; do not buy expensive models merely to populate a table. Current user preference rules out treating earlier broad API access as an instruction to spend again on Claude, Gemini or premium alternatives.

## E. Optional mechanism experiment only if needed

A future evidence intervention could ask whether a compatible conditional dependence result changes a generator's scientific analyses. That is separate from the main research-request comparison. It needs a frozen source packet or controlled evidence release, matched authoring conditions, no target answers and predefined analysis changes. An open-retrieval result alone does not establish that finding a particular paper caused improvement, because structures and other evidence also change.

The present evidence already supports a useful interpretive contrast: all twenty delivered fixed-packet initial laws underrepresented residual dependence, whereas the current request-only BP laws are close to the BP sample reference. This is a motivation, **not** a controlled retrieval-effect estimate. Do not retrospectively label the prior packets "weak" and the newly successful packets "strong" as if that treatment had been randomly assigned.

Likewise, uncertainty prediction by provenance tags is a different project. A retrospective label assigned after seeing target discrepancies cannot validate an ex ante risk predictor. Such a claim would require prospectively frozen labels and a genuinely unexposed reference or rigorously declared new estimand boundary. No fresh eligible target is created by this plan, and a new data family is not necessary for the current development-focused paper.
