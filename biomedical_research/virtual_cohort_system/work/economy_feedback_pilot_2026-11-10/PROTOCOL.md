# Economy pilot: actual generated-data feedback versus ordinary second look

The user's latest instruction authorizes continuation with Sol as the workhorse, limited Astra and low-cost DeepSeek. This unit uses at most **12 API calls**, allocated8 Sol,2 Astra and2 DeepSeek, under a total USD10 reservation ceiling (OpenAI8, DeepSeek2). No Fable or Carbon request is possible through the allowed roster. Historical per-attempt means suggest roughly USD3 for twelve fresh requests, but four requests here include prior artifacts and feedback; that is not a promised cost. Actual reservations and usage are recorded before and after each call.

## Question

Can measured checks of an Agent's own virtual data help it improve physical/internal consistency more than an ordinary second look at the same submission? Which statistical relationships remain assumption-dependent despite that opportunity? The deliverable remains analyzable virtual biomedical data. A feedback benefit is not a required positive finding.

The earlier shared prompt already distinguishes reported statistics, parameters and requested estimands. Repeating a longer generic checklist would add little information. Here the contrast is access to actual generated-data observations, with the initial scientific construction held identical across review branches.

## Design fixed before new outputs

Each of the two existing cases (PNS-context blood pressure, Turkana-context lipids) has four fresh initial authors: Sol_A, Sol_B, Astra and DeepSeek. Sol_A is the paired parent selected in advance. Sol_B and the other models are independent reference constructions, not fallback parents and not a balanced multi-provider efficacy experiment.

Each Sol_A is frozen and sampled at three diagnostic seeds. Two new, independent Sol API requests then receive the same source packet, the exact same earlier submission and the same general review instruction. One receives the recorded own-generated diagnostics; the other receives no generated observations. There are two paired parents, four review requests and eight initial requests. The order is counterbalanced by case, not by measured quality.

The authors choose the statistical law and scientific values freely. The host supplies no desired rho, slope, SD, component decomposition or target difference. Bibliographic/statistical evidence is identical to the previous pilot, with no new retrieval. The diagnostic table describes the **generated task population**, not real target observations and not a replay of any source cohort. It must not be labelled a source-fit certificate. Primary endpoint and physical-component formulas are unchanged trusted estimators already specified for these tasks.

A deterministic delivered generator may be reused for local draws at the prescribed seeds without additional API calls. All code executes only in the existing WSL/bubblewrap sandbox. No unrestricted fallback or host import of generated code is allowed.

## Readout and interpretation

The primary readout is the physical-component violation fraction on fresh evaluation draws (SBP below DBP; HDL above TC), reported with complete delivery availability. Report parent, ordinary-review and feedback-review values for each case, and the branch contrast from the shared starting point. A parent with no observed violations presents no demonstrated improvement opportunity on that metric. Reporting-only edits are not data improvements.

Secondary outcomes retain all requested adjusted slopes, residual dependence, marginal SDs, traceability and independently audited exact-estimand claims. Compare predictions with the existing aggregate reference only as developmental analysis, including the reference uncertainty. The same known target was already exposed to the host in earlier work; this unit is not a new independent clinical validation. No generated or target result is used to select a better parent or to add another revision.

Two paired parents support a small mechanism probe, not a significance test, general feedback superiority, or a model leaderboard. Missing joint evidence may remain missing even if software and mathematical claims improve. A negative or no-op result ends this unit as scheduled. No new component is justified merely to make the reference match.

Every request records provider/model IDs, prompt, captured response, public token metadata, tariff estimate and provenance hashes. Review claims and code/spec changes are distinguished. The old twenty-call experiment, manuscripts and frozen historical records are not changed.
