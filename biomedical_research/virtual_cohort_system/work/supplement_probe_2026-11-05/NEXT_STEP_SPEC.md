# Next bounded development step — proposal, not frozen or executed

## Scientific question

Can the Agent turn the newly obtained source regression information into an explicit, defensible change in a data-generating model, while keeping unsupported conditional relationships visibly assumption-dependent? The endpoint remains generated data's scientific-analysis utility. The present supplement probe did not evaluate that endpoint.

## Minimal sequence

1. Give a fresh constructing Agent the existing allowed source packet, research request, and this increment with reported/inferred/absent fields intact. Do not supply exposed target effects. Let it choose the scientific structure, parameters and whether a revision is justified. No controller-written BMI coefficient in its generator.
2. Before any generation, obtain a short scientific change proposal: which source statistic can constrain which source operator, how source and target differ, and what happens to the old unsupported joint/dispersion assumptions. An unchanged candidate is a valid outcome. A declared percent-scale interpretation of S2 can be used as a working hypothesis if checked against the source descriptions; it cannot be relabelled a printed unit or exact target coefficient.
3. Replay only the compatible source statistics in their stated source context. The source's age bands, diabetes exclusions, sampling context and incomplete fasting-time specification cannot be silently replaced with E01 target conditions. If a complete source replay is impossible, report a conditional/sensitivity check rather than a verified source fit. Missing coefficient SE/CI stays missing.
4. Only after the proposal and analysis choices are fixed, generate a small development batch and run the same predeclared scientific analyses. All old candidates/receipts remain intact. E01's target was already exposed; any result is development evidence, not a new independent confirmation.

## Attribution

An old-packet/new-packet comparison can test the **value of additional evidence**. It cannot establish superiority of an acquisition policy, since information differs. A subsequent workflow claim would need the already proposed equally capable free Agent, same tools/evidence access/total budget and review opportunities. Do not invent that claim merely because this source probe succeeded.

The old E01 static specification already used the positive partial correlations later supported by the supplement. Confirming their signs alone supplies provenance, not a new parameter or expected quality gain. The fresh proposal must explain any genuine new use of the printed regression magnitudes; otherwise retention is the correct result and another generation batch is unnecessary.

Do not freeze a large campaign now. The first decision is whether the fresh Agent produces a substantively different scientific construction from this partial increment. Stop this mechanism branch if it changes only documentation, silently borrows target answers, or cannot explain the source-to-model mapping. No need to force improvements in the glucose-adjusted effect or conditional variance: this supplement does not identify them.

## Implementation scope

The current `.doc` probe is a one-file route, not an automatic upgrade of `evidence_actions_v1` or the old gateway. A future controller needs a versioned action-completion interface and budget accounting before general online use. Do not generalize the downloader or create more roles merely to claim autonomy. Preserve the useful narrow adapter, source increment, failed/unsupported cases and intervention accounting.
