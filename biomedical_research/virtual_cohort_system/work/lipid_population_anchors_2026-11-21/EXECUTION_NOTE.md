# Technical note during first outcome access

The first run after the sealed-predictions commit opened both surveys in the registered order. The first period's six estimates were calculated in memory. The second period stopped on a Windows-1252 apostrophe (byte 0x92) in a demographic variable label, before its cholesterol files had been acquired. The script printed a decoding exception and did not emit or save either period's estimates. The original opening receipt remains the first access. At the time of this note there was no RESULTS.json.

The compatibility reader converts a variable's label to UTF-8 only when its bytes fail UTF-8 decoding. It forwards all numeric data, IDs, weights, variable names and estimator operations to the unchanged registered code. No author, model, numerical prediction, eligibility criterion, measure, inference procedure or decision threshold is reopened. The independent reviewer uses ReadStat to read the original XPORT bytes separately. The replay is identified here so the initial failure remains visible.
