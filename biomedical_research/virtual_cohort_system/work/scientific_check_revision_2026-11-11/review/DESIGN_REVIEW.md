# Independent design review: paired scientific-check revision

Status: design review only; paid execution is not approved by this document. Implementation, freeze and boundary verification remain pending.

## Question and unit

The design can test whether a structured review requirement changes problem detection, revisions and downstream analysis results relative to a capable generic review, starting from the same frozen generator and evidence artifacts. It is a paired developmental revision study of twelve existing laws, not another request-only construction study or a fresh independent clinical validation. Both review policies receive the same tools; the treatment is the structured prompt plus review/finalization requirements, not exclusive access to a checker.

Each original law is the paired unit. It has two fresh reviewer sessions and three fixed final sampling seeds per selected branch. Keep original construction policy and clinical context as grouping metadata; do not turn seeds, endpoints or rows into independent clinical cases. Existing references are already exposed at project level. Any original author's target-family preview exposure persists in the lineage even if the new reviewer receives only captured full-text sources.

## Required preflight properties

1. Include all twelve frozen laws under an immutable roster. Bind generator, specification and notes byte-for-byte to the old selected program. A new v000 import manifest may wrap those bytes; preserve the old manifest binding separately.
2. Both branches receive the identical initial request, initial scientific artifacts, source versions and tool capabilities. No clinical estimates, old evaluator output, audit verdicts, suggested signs, desired correlations or numerical repairs enter the new reviewer context.
3. Preserve full provenance and source uncertainty. If original code or notes identify their origin, do not claim complete identity blinding merely because new session IDs are neutral.
4. Count imported v000 separately from the stated allowance for new submissions. Count source imports separately from new retrievals. All extra model calls and checklist tokens count against the same per-branch ceilings.
5. Generic review can search, inspect, test, retain and revise. Structured review can honestly return unknown or unsupported instead of being forced to pass each dimension. Explicit inability remains permitted.
6. No timeout, malformed answer or exhausted budget silently becomes a successful v000 retention. Retention requires the review Agent's explicit terminal selection; incomplete branches remain unavailable.
7. Static mathematical flags are bounded heuristics, not a proof of finite moments or a theorem of divergence for every matched expression. Every output must identify its inspection scope. Finite output summaries cannot certify population moments.
8. Physiological rules are declared hypotheses/identities with source or assumption labels. The tool computes their violations without certifying medical validity. Unsupported variables, nonfinite coefficients, unsafe operators and incoherent units must not produce a false pass.
9. Joint-relationship checks distinguish source reporting, algebraic implications and unverified modeling/transport assumptions. Missing evidence is not an instruction to set a relationship to zero or to target a known clinical value.
10. Old programs and data remain unchanged. Any generator execution uses the existing isolated worker only. Imported sources, new retrievals, tool outputs, candidates, review contracts and final selection bind to hashes and versions.
11. All 24 review branches must close before new final sampling and clinical comparison. Retain all planned slots and report every failure. No intermediate reference comparison decides which branch proceeds.
12. Report mathematical/physiological repairs, unresolved evidence and scientific-analysis changes separately. A lower reference discrepancy does not prove that a repair caused better population fidelity. No result-dependent equivalence threshold or combined quality score is introduced.

## Interpretation limits

The review requirements may increase token use or make finalization harder; equal ceilings are not equal realized effort. A favorable result identifies this workflow bundle within these laws, not the separate causal contribution of each checklist dimension. If both policies use the new tools successfully, that is useful application evidence rather than treatment contamination to be suppressed. A mathematical correction can be necessary even when a particular finite-sample coefficient becomes less close to the clinical reference.

Independent verification should inspect changes against original source/code support, separately recompute retained final tables, and keep the original-law findings distinct from repaired-law findings. The public report should not classify a documented but unsupported statement as validated confidence or automatic source extraction.
