# Harness interface: first milestone

This reference describes only the artifact interface implemented for the first milestone. At the harness project root supplied with the task (the directory containing `cohort_harness/`), read `README.md`, current task examples and CLI validation messages for exact field schemas. This skill may be installed outside that project, so do not infer the project location from the skill's parent folders. Do not infer unavailable tools from a proposed future architecture.

## Available boundary

The harness checks task/candidate contracts, calculates declarative source statistics from submitted tables, and records frozen candidate and revision artifacts. It does not execute `generator.py`, invoke an LLM, search the web, screen newly retrieved papers or isolate processes. Independent target-data evaluation is outside these four commands.

Approved source artifacts enter through the supplied registry with their hashes. Agents may cite admitted artifacts and explicit assumptions; they must not manufacture approval records to admit their own evidence. A hash establishes which bytes were used, not their scientific truth or applicability.

## Candidate bundle

The task bundle contains its task description, allowed inputs and source registry. A candidate is placed at:

```text
<bundle>/candidates/<name>/
  evidence.json
  model_spec.json
  decision.md
  checks.json
  generator.py OR generated.csv
  source_checks.json             optional
```

Submit exactly one of `generator.py` or `generated.csv`. This is an output-route choice, not a statement that either route is better. Whole-cohort, enrichment and completion tasks follow their own task-defined preservation and output requirements.

For the program route, define a top-level synchronous `generate(observed, spec, seed)` returning a pandas DataFrame. The harness will call these three arguments positionally: permitted observations (None for whole-cohort mode), the submitted model specification, and a seed. Parameter names may differ, but exactly three positional parameters and no variadic or keyword-only parameters are allowed. Use the specification for scientific settings. A deterministic construction may ignore the seed when explicitly justified. Syntax/signature acceptance does not execute the body or verify its behavior; no file/network access is part of this interface.

- `evidence.json`: admitted sources, reported statistics and scientific context.
- `model_spec.json`: model choices, parameters and evidence/assumption references.
- `decision.md`: concise rationale, applicability, unresolved limitations and stopping reason.
- `checks.json`: implementation or other checks actually performed, with their scope.
- `source_checks.json`: optional declarative checks linked to evidence items, table artifacts, operators, status and assumption references under the supported schema.

Do not place hidden reference data or their derived statistics in the bundle. The supplied-source tables for replay represent a source population; they are not target validation outcomes. If a source check needs unreported covariates or joint distributions, disclose the approximation or inability to compute it.

## Commands

Run from the project root using the configured Python environment:

```text
python -m cohort_harness validate --bundle PATH --candidate NAME
python -m cohort_harness source-checks --bundle PATH --candidate NAME
python -m cohort_harness freeze --bundle PATH --candidate NAME
python -m cohort_harness verify --bundle PATH --candidate NAME
```

For a revision:

```text
python -m cohort_harness freeze --bundle PATH --candidate NEW_NAME --parent OLD_NAME --revision FILE
```

Keep `OLD_NAME` intact. Populate the revision file according to the implemented schema and explain the actual change or no-op. Do not reinterpret changed prose as improved generated data.

`validate` checks artifact contracts. `source-checks` calculates supported source-statistic operators on supplied simulated tables. Its output explicitly leaves simulated-table provenance unverified: it does not establish that the table was generated by the submitted program. `freeze` records candidate commitments; `verify` checks recorded integrity. None of these operations certifies scientific accuracy, provides hidden-target feedback or changes the available evidence budget.

If a command rejects an artifact, fix its declared contract or record the limitation; do not bypass source approval or inspect hidden outcomes to make it pass. Preserve command outcomes honestly, including unsupported operators and failed checks.
