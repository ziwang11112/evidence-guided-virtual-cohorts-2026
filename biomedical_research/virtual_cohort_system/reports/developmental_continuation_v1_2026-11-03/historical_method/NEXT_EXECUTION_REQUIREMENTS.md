# Conditions for the next execution release

The current pilot is closed before generation. This document does not reopen it, allocate another budget or authorize a new constructor. Its purpose is to prevent another round of framework work from obscuring the scientific question.

## Preserve the scientific question

Use the existing evidence, five-variable whole-cohort task, three source contexts and three target analyses. Keep CHNS explicitly developmental. The question remains whether one evidence-generated dataset supports useful biomedical analyses, including uses not fed back during construction. Numerical source feedback is one mechanism to test, not a required superiority claim or an end in itself.

The two current scientific constructions may be reused only if a future release explicitly identifies them as reused, preserves their original failures and proves that generator/specification/evidence/law bytes have not silently changed. A technical alias correction is not an independent scientific construction and not an observed quality improvement. A new scientific decision must be recorded as such. No parent or child is relabelled as a fresh blind replication.

## Resolve the demonstrated interface defect once

1. Give the author a complete interface and a read-only metadata checker before submission. The checker validates actual source-native aliases, unit mappings and operator contracts, and reports every affected context together. It neither selects a scientific law nor repairs a value.
2. Require original `bindings` to be `{}`. Native aliases must connect an existing generated column to the evidence's named measurement representation, with the required assumption declaration. A name change cannot imply a new specimen or assay equivalence.
3. Keep the final actual bound validator after bridge preparation and genuine review. Early metadata success does not stand in for freeze, provenance, moment, support, runtime or target-use checks.
4. Independently verify any prospective technical correction preserves the generator, scientific parameters, evidence and intended numerical operator. Do not let an interface fix introduce source fitting, a new dependence or a target effect.

The repeated shared errors also expose a usability problem in the harness. The Agent should decide measurement identity, source applicability and scientific assumptions once, rather than manually repeat equivalent names across several metadata files. A later interface can derive mechanical aliases and bindings from one explicit variable dictionary, refusing ambiguous mappings instead of guessing them. Such a compiler would be an engineering simplification, not an additional biomedical contribution. The present repair only detects these errors; it does not implement or validate that compiler.

## Run before adding more architecture

Once a separately reviewed release sets the remaining execution and revision allowances prospectively, prioritize the complete source → permitted feedback → frozen target-analysis path. Do not acquire another cohort, add a new optimizer, train a model, introduce more Agents or widen the scientific endpoints merely to avoid an unfavorable outcome. Keep all planned versions, no-op decisions, failures and unassessed uses visible.

The latest numerical source fit is encouraging but is not evidence that these two new laws preserve target relationships. In particular, age/sex independence is currently an assumption. A failed age analysis would locate a limitation in available evidence and joint modelling; it must not trigger hand insertion of a known target coefficient. Source fit, mathematical support, numerical reproducibility and downstream scientific utility must remain separate reported results.

The next meaningful research milestone is a complete, independently recalculated analysis-use profile, not another software test count. Final method freezing should await that profile, an explicit limitation statement and stable executable interfaces.
