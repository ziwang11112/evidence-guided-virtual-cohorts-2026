## Aggregate verification-record schema correction

Production preflight exposed a false positive at `INDEPENDENT_RESULT_REVIEW.json` → `additional_independent_row_checks.records`. Those entries contain one recomputed aggregate per run/endpoint, not individual records. The exception now applies only to that exact public filename and JSON path. It requires the exact container and record keys, 1–30 entries with a matching integer count, bounded run identifiers, five enumerated aggregate endpoints, unique run/endpoint pairs, finite non-Boolean numeric values, nonnegative differences and a matching maximum difference.

Tests reject patient-row collections and extra patient fields at the same path, and reject equivalent-shaped records elsewhere. Generic `records` handling remains unchanged. The targeted exporter suite passed all 20 tests with `--basetemp work/pubfix3`; a preceding run's only failure was Windows path length in the longer fixture path (19 passed), not an export-policy failure. A final dry inspection checked all 47 selected files without creating transport. No other reports, author-bundle files or publication state were changed for this correction.
