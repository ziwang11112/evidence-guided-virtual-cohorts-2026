# M15-A frozen source-only direct-table protocol

Purpose: determine whether one Agent can directly author a small fictional table that approximately reflects a bounded published descriptive packet, and inspect what its unreported same-table properties look like. This is a SOURCE-ONLY engineering pilot, not evidence of clinical validity, target-population utility, participant reconstruction, or an independent validation study.

The controller and parent Agent already know all four held-out urate SDs from the task and source audit. A fresh builder must receive only the screened visible directory; its context must not inherit controller history. Blinding is procedural, not enforced by filesystem isolation. Prior model training or source recall cannot be excluded. The private XML, holdout JSON, this protocol, evaluator, preparation script and previous urate audit must not enter builder context. Do not give the builder other source estimates or a scientific mean formula.

Source admission is a narrow task authorization: U1 Yun 2021, DOI 10.1038/s41366-021-00810-9, PMC8236402 Table 2 Adult cohort plus limited Methods context. The full original XML is retained privately. Twenty moments are visible: each of four race/sex groups contributes age mean/SD, BMI mean/SD and urate mean. Source group sample sizes are context. All four urate participant SDs are held out together. They are from the SAME SOURCE and SAME TABLE, not independent external truth. Adjustment and standardization are not applicable to these descriptive quantities. No regression, mediation, sex interaction, curvature, or quartile relationship from the article or any other paper is admitted.

Artifact contract: 128 fully Agent-authored fictional rows; exact columns sample_id,race,sex,age,bmi,urate; counts White male 38, White female 46, Black male 19, Black female 25. Only sample_id has identifier role; all other fields are generated. Age is 20–56 inclusive, BMI >0 and urate >=0. No target files, target downloads, real participant data, existing generator imports, fitted generation programs, random sampling by controller, code-created row values, rescaling or optimizer repair. Builder writes literal CSV using apply_patch. Controller code may validate/hash/compute diagnostics and copy byte-identical artifacts for receipts or an explicit retain decision; it never populates or repairs row values.

Schedule: freeze this protocol, evaluator, evidence packet, templates, prompts and private holdout before starting a fresh builder. Use one builder for initial and the same builder for the sole optional follow-up. Keep the initial table and its candidate artifacts immutable. Validate/freeze/verify with existing cohort_harness. Then consume exactly one numerical feedback pass, returning structural errors and the twenty visible moment errors only. No hidden SD, within-group urate spread diagnostic, regression, quartile, rank, sign or exploratory feedback. The Agent either directly authors one revision or explicitly retains; freeze a final child with truthful revise/retain metadata and bind the exact feedback in checks. Even a no-op requires a final candidate freeze. No new data-generating attempt after final, no selection among repeats and no budget reset after failure.

Failures: record every preparation/command/submission failure and any actual changes. The existing harness refuses invalid candidates. If either version cannot be frozen and verified, report the bounded run as failed/incomplete and do not evaluate hidden values. A failed numerical feedback attempt consumes the pass; it is not silently reset. Do not repair rows in controller. Failure to pass is an outcome, not permission to expand the budget. Additional pre-feedback structural error messages are allowed only to document failure; they do not authorize extra candidate attempts.

Scoring is fixed in controller.py. Means are arithmetic and SDs use ddof=1. For each of 20 visible moments, error = abs(observed-reported)/abs(reported), retaining observed, reported and absolute errors in original units. Report each error and separate mean absolute error and mean absolute relative error for age (8 items), BMI (8), urate means (4). The optional joint 20-item mean relative error is descriptive engineering aggregation, not a clinical performance score. There are no numeric success thresholds or hypothesis tests.

Only after BOTH initial and final freezes, lineage and actual feedback binding verify, calculate the four held-out urate SD relative errors and their arithmetic mean for both versions. No clinical confidence intervals: 128 directly authored rows are not iid participant evidence. Summarize observed changes honestly; better fitted visible moments do not establish better held-out properties.

Prespecified same-table exploratory analyses for both frozen versions: OLS urate ~ 1 + age + BMI + male + Black; curvature model urate ~ 1 + age + z + male + Black + z^2 with z=(BMI-28)/5; separate interaction model urate ~ 1 + age + z + male + Black + male*z. No combined curvature/interaction search. Report coefficients, matrix rank, descriptive R-squared, residual sum of squares and condition number; rank deficiency is non-identifiable, not a success. Compute within-sex urate quartiles using linear quantile boundaries, ties kept together with Q1 <= q25, Q2 (q25,q50], Q3 (q50,q75], Q4 > q75; report boundaries, n, mean age/BMI/urate and Black fraction. Empty quartiles remain empty. These have no external reference truth, no p-values, no sign-success criterion, and no clinical or causal interpretation.

The original harness source files are reused unchanged. No framework module or engine test is added. The evaluator is local to this work directory. Hashes verify bytes and procedural ordering; they are not a security sandbox or proof against deliberate tampering. Numerical candidate evaluation remains pending until the parent authorizes the actual run.
