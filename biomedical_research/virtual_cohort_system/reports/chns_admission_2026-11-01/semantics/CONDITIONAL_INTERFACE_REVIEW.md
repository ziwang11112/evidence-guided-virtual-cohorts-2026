**The exception changes weighting interpretation, not the declared statistic.** Only named Pearson and Spearman are admitted. Their conditional, source and strict-recipe operator signatures must agree (lines 124–128), including variable roles, selection and missing-policy declarations. Other statistic kinds, known selection changes, unit conversions and changed adjustments are not authorized. The calculation uses the existing Pearson or average-tie Spearman implementation; it does not introduce a new statistical engine.

**Approval is exact but procedural.** Approval must cover the entire canonical plan payload, contain complete evidence dispositions, identify a reviewer distinct from the builder, and designate exactly the requested evidence items as interpretation-approved (lines 30–69). Quarantined/unapproved items fail. Each evidence item and strict check can be requested once, and the plan allows at most 12 interpretations. Distinct declared weighting and applicability assumptions are required. These checks bind declarations; they do not authenticate identities, prove faithful source extraction, or determine whether assumption prose is scientifically sufficient. The report correctly states those limits.

**Existing output is verified before conditional arithmetic.** `_compute` verifies the candidate freeze and requires the interpretation plan, approval and strict sidecar to be committed. It then calls `strict.verify_feedback` for the exact candidate and run (lines 161–167). That verifier in turn checks the retained execution/output and recomputes strict diagnostics. The added canonical typed comparison runs at lines 168–173. Selected strict rows must still have `not_computable`, null calculation and null difference before the conditional calculation at line 198. The data path is the verified run's generated CSV, not a caller-supplied comparison table. This module neither runs a generator nor creates a source-context population. Verification may recompute statistics on the same retained output; it does not authorize new biological tables.

**Artifacts remain separate.** Collection rejects an existing conditional feedback ID, writes only the new conditional folder and subsequently verifies the report (lines 229–242). It does not change strict sidecars/reports, candidate artifacts or legacy code. Bindings include task, evidence, recipe, semantic sidecar, model specification, candidate freeze, conditional plan, approval, strict report and generated table hashes; the inherited engine/runtime record adds the new module hash (lines 213–218). The strict report transitively binds the execution receipt. Conditional verification requires the exact file set and canonical JSON equality against recomputation (lines 245–264), preserving numeric-type distinctions in the new report.
