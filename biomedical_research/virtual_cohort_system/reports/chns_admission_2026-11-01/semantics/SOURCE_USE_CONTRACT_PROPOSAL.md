# Minimal source-use contract for the CHNS candidate

1 November 2026. **Proposal, not admission, implementation or F2.** Based only on existing local source audits, source-use decisions and interface code. No original was reopened, participant data accessed, generator executed or shared state changed.

**Recommendation:** freeze one explicit source-use manifest and use semantic feedback v1 on the existing whole-cohort route. Do not build a source replay component before identifying at least one admissible numerical check—strict or explicitly conditional under the separate interpretation design below—and reserving its additional tables. A useful evidence-informed construction can proceed with declared joint-distribution assumptions; complete identification of the five-variable distribution is not an admission requirement. Conversely, an unsupported source estimator cannot become executable by calling its discrepancy approximate.

## What the existing interfaces actually do

- `whole_cohort_feedback._read_plan` requires the feedback population to equal the execution task population and permits identity measurement only ([code](../../../cohort_harness/whole_cohort_feedback.py), lines 43–74). It cannot relabel CHNS-like output as a Lifelines, Shanghai or MIND population.
- `semantic_feedback_v1.preflight` checks declarations without reading individual tables. Collection computes from one successfully verified whole-cohort output; it neither generates a source population nor certifies source applicability ([code](../../../cohort_harness/semantic_feedback_v1.py), lines 199–320). Unknown weights/transforms yield null calculations; known operator mismatches reject before arithmetic. Missing source n or sampling precision alone does not block a raw discrepancy.
- Existing replay v1/v2 require enrichment inputs; v2 explicitly rejects a whole-cohort task ([code](../../../cohort_harness/source_replay_v2.py), line 115). These are not ready-made CHNS whole-cohort replay paths. Their older semantic checks must not replace v1.
- The execution adapter already accepts whole-cohort tasks without observed rows and stages the task, model specification and generator ([code](../../../cohort_harness/execution.py), lines 202–232). This is sufficient infrastructure for a small future context adapter; a new statistical engine is unnecessary.

## One frozen manifest, three distinct uses

Add a proposed `source_use_contract_v1.json` as an auxiliary artifact of **new** candidates, with the following explicit content. Do not alter historical receipts or claim this schema already has a validator.

| Field group | Minimum content |
|---|---|
| Identity | Version; task, admitted packet, measurement contract, exposure decision and operator-engine hashes; approval record; exact permitted evidence IDs. |
| Item disposition | Original locator; reported versus algebraically derived status; `numerical_check`, `context_only`, `unavailable`, or `quarantined`; reason; dependency group so alternative units/derived ratios are not independent evidence. |
| Scientific meaning | Original population and selection; variable/assay/time definitions; statistic roles, adjustments, denominator, units, weighting, transform and missingness; source n and uncertainty roles separately. Unresolved fields stay explicit. |
| Use and execution | `target_population_proxy` or `source_context_diagnostic`; context/task ID; approved check IDs; exact v1 recipe/sidecar hashes; applicability assumptions; no inference of a source context from an item label. |
| Construction and budget | Two independent constructors; stage/seed schedule; allowed feedback; table/row/resource ceilings; revision stopping rule; complete retention and final evaluation schedule. |

The **builder packet** contains only approved external facts, their uncertainty/limitations, intended population and measurement metadata, and the task. Contextual facts may inform an explicitly labelled model assumption; they are not hard constraints. Quarantines are exclusions, not hidden calibration targets. A new-context builder must not receive old fitted candidates, ENSANUT results, CHNS source-family results, incidental codebook moments, patient rows, empirical target margins or reference effects. Root defines questions and information boundaries; the builder chooses the joint model, parameters and transport assumptions.

Three labels must survive into every report and revision prompt:

1. **Source evidence review:** extraction/consistency/availability feedback, without a synthetic numerical discrepancy. This is usable now after item admission and must not be described as achieved source fit.
2. **Target-population proxy:** an otherwise valid source statistic evaluated on the generated target-population table. It is a transport diagnostic, even if its arithmetic and source semantics match. It must not be labelled source-population replay. Unknown essential source semantics still produce no number under v1.
3. **Source-context diagnostic:** the same construction evaluated under an explicitly generated source-population/measurement context. This can support a source-conditioned comparison, but the context is an assumption-dependent reconstruction, not the actual source participants or proof of source-population equivalence.

## Resolve omitted weighting with a conditional interpretation, not false provenance

Bao explicitly names Pearson and MIND explicitly names Spearman. It is scientifically defensible to adopt the conventional equal-weight version of either named estimator **as an independently approved interpretation assumption**, while the original analytic weighting remains unreported. Demanding the literal word “unweighted” in every paper would be an unnecessarily strong requirement for this conditional use. The assumption supports a conditional comparison; it does not establish the author's actual analysis or cure population/measurement differences.

**Current v1 cannot encode that distinction by itself.** Its sole `weights` field is the declared source weighting; `not_reported` deliberately makes the source discrepancy unavailable. Keep that strict sidecar and output unchanged. Do not write `none` there, relabel the original evidence, route through the legacy collector, or describe the resulting number as faithful source reproduction.

The smallest additive alternative is an opt-in **interpretation-comparison layer**, not a new statistic or general weighting implementation. Its frozen manifest contains original evidence/sidecar hashes, `original_weight_status: not_reported`, `interpretation: conventional_equal_weights`, `basis: named_estimator_plus_approved_assumption`, the explicit Pearson/Spearman operator, review record, assumption IDs and actual execution-context ID. Limit this exception to these named correlations, with at most one approved interpretation per evidence item; do not use it for known weighted Pani estimates, uncertain quantile algorithms, altered adjustment sets, unknown units or quarantined values.

After the whole strict plan has passed structural preflight, this layer can validate the interpretation's operator, variable roles, units and types using the established validation logic and calculate with the existing correlation implementation on the already verified output. Other substantive gates remain explicit; the weighting interpretation alone cannot repair an unresolved missingness/selection operator or authorize a measurement conversion. A complete generated post-analysis distribution may be an approved modelling assumption, with its limits retained, rather than a claim to reconstruct an unknown imputation procedure.

Write a **separate conditional report** with the original strict result still unavailable, `original_weight_use: unknown`, `assumed_weighting: equal`, the reported coefficient, computed coefficient, raw difference, interpretation approval and all task/output/engine bindings. Its scope is `conditional_source_interpretation_target_proxy` or `conditional_source_interpretation_source_context`, never `matched_reported_source_estimator`. Do not count conditional checks as strict computable checks or pool their status. Unsupported cases remain null. There must be no automatic fallback when v1 fails; the conditional branch must be named and approved before any run.

This gives a bounded practical choice: approve conventional interpretations for the two named methods and add only this small, tested reporting/validation layer, or retain nonnumeric evidence-review feedback. The first option can use existing target tables, with no new context tables, while explicitly remaining target-population proxy feedback. A source-context adapter is needed only for the stronger separately budgeted comparison. Focused invented-data tests must show that known-weighted/mismatched/quarantined inputs cannot enter this branch, strict records remain unchanged, assumption approval is mandatory and report/output tampering fails. This is a proposed versioned contract change; no such permission or computation is implied by the currently installed v1.

## Smallest optional source-context interface

Only if a numerical source-feedback loop is selected and an item passes admission, add **one versioned whole-cohort context adapter**, separate from the frozen collectors. Proposed interface: `preflight_contexts(bundle, candidate)`; `run_context(bundle, candidate, context_id, run_id, seed, limits)`; `verify_context(...)`.

For this bounded case allow at most **one named external context**, with no participant input. Its manifest supplies a reviewed source task, native variable definitions/units, context assumptions and source-specific v1 recipe/sidecar. Compile a new child whole-cohort bundle; run the existing execution adapter; then call v1 collection/verification. Bind parent freeze, approved context manifest, child task, evidence, model specification, generator, receipts and output hashes. Validate all context declarations before any execution, keep unavailable checks, use append-only IDs and never fall back to legacy feedback. The parent task remains unchanged.

For the program route, generator and model-specification bytes stay identical across source and target tasks within a stage. The builder declares which scientific parameters are shared and which population/measurement parameters vary; context selection uses a fixed task/context identifier. The adapter never supplies coefficients, fits a relationship, fills covariate rows or silently converts plasma to serum. Byte identity alone does not prove shared scientific structure: independent review must reject an unrelated source-fitting branch presented as transfer of the target model. Native source units avoid a hidden conversion in the collector; any generator-side measurement mapping remains a declared, reviewed model assumption.

This adapter need not add latent medication/pregnancy fields to the target task. A generator can model an already selected source population directly, documenting its eligibility-conditioned law. It cannot claim that removing unrepresented exclusions from a broad generated population reproduces the source. A direct-row construction remains valid for the main whole-cohort experiment; separate source rows would be a **paired source-context submission**, not verified rerunning of the same program. Do not force the program route merely to qualify for whole-cohort research.

## Bounded target-reference choice: the released-data population

**Recommend a prospectively declared released-data all-comers reference**, conditional on its frozen age/wave eligibility and required-field availability. This is defensible when actual field identities, numerical units and the categories required by E1/E2/E3 are known. It does not require an exhaustive catalogue of undocumented positive sentinels. Its claim is association utility against this specified public release under a residual release-quality assumption, not verified underlying population truth or faithful reproduction of every external source's exclusions.

Use native reader-recognized missing values; preserve documented missing reasons where available. Apply the documented `GENDER` 1/2 whitelist, treating other values as unavailable for that projection. Apply only exact, release-compatible flag actions. The coordinator reports newly recovered labels including height/weight code 9 “set missing,” height code 11 “average height,” weight code 4 “extrapolated,” and weight code 2 “converted Jin.” Bind their definition-crop provenance in the measurement contract before use; this proposal did not independently re-extract those labels. Mask values explicitly labelled set missing; retain released corrected/averaged/extrapolated values and their flags under the stated released-data policy, rather than applying the historical correction again or excluding all positive flags. That retention is a declared reference choice, not evidence that every correction is clinically accurate.

Do not invent universal 88/99 masks, derive cutoffs from target distributions, or treat assay operating ranges as missing codes. A missing flag is not a clean-record certificate. Freeze the complete-case rule and handling of mathematically undefined BMI before analysis; an undefined quantity must not enter OLS. Avoid undocumented medication/pregnancy exclusions by explicitly choosing all-comers, while retaining the resulting source-population mismatch. Never silently call this a nondiabetic, untreated, nonpregnant or source-matched cohort.

Unknown individual fasting adherence, incomplete assay comparability, timing differences and unmeasured exclusions ordinarily remain **measurement/transport limitations** under this choice. Actual ambiguity over which field is central versus field glucose, mmol/L versus another numerical scale, the HbA1c scale, or the required category coding would instead block the affected primary estimand. Unknown positive missing-code completeness is a residual release-quality assumption when no authoritative field-specific alternative is documented; it is not proof that positive sentinels do not exist.

End dictionary research once existing official metadata and the recovered labels have one independently reviewed field table. Freeze this released-data policy without inspecting target effects. At the single reference stage, preserve any newly encountered coding inconsistency as a quality failure; if it makes a required quantity uninterpretable, withhold that estimand or stop the case. Do not try alternative recodings against target outcomes or present a repaired post-reveal analysis as fresh validation. Ordinary missingness/flag counts may be reported under the frozen policy but cannot be sent back for construction. This bounded choice replaces an endless demand for perfect missing-code information; it does not relax source-operator matching or certify transport assumptions.

## Budgets, acceptance and stopping

**Default executable schedule:** at most 2 constructions × (initial + at most 1 revision) × 3 predeclared seeds = **12 target tables**. No biological warm-up, best-seed search or unlogged calibration tables. Use one seed list fixed before construction; initial and revised outputs use the same list. Propose at most 10,000 rows and the existing 20,000,000-byte output ceiling per table, 30 seconds, 1,024 MiB and 100,000 log bytes per attempted execution; freeze any justified changes before running. Failed attempts consume their scheduled slot and remain visible; repairs cannot silently create extra scientific attempts. Generated n is a Monte Carlo setting, not a source sample size or an uncertainty remedy.

For direct-row submissions, copying one table into three execution receipts does not create three random replicates. The protocol must bind three separately submitted draws to one frozen construction policy, or explicitly report that Monte Carlo replication is unavailable. Preserve the direct-row route without falsely attributing seed-controlled generation to it.

**Source tables are additional tables.** The default contract allocates **zero**. With one source context, fully pairing every construction/stage/seed would require up to **12 additional source tables**, or 24 total. That is an explicit proposed schedule change, not implied by the 12 target-table schedule or by the separately optional 24-table mechanism pilot. Do not execute the extension until the parent resolves it against the authorized budget. Otherwise retain evidence-review/labelled proxy feedback, skip unavailable numerical revisions, and state the resulting narrower claim. Recomputing a statistic from the same retained table is verification, not permission to generate a replacement table.

Cap the frozen feedback recipe at 12 source checks for this case; retain every admitted/unavailable/quarantined item in the ledger even if it has no numerical check. No new source read is needed just to fill that cap. New-original consumption remains 2/6, the target-family ceiling remains three, and the acquisition limits are unchanged. The builder receives no new literature/tool access beyond its approved packet during construction; any required additional information returns to admission before a new frozen campaign.

Accept the **contract** when: required target field identities/units/categories are supported and the released-data decoding policy and residual assumptions are explicit (or affected uses are removed); population and E1/E2/E3 are fixed without target effects; each source item's role is settled; every executable check passes v1 preflight and independent source-semantic review; the chosen feedback mode and table budget are explicit; and a fresh-context information boundary and final reporting plan are in place. This does not require a uniquely identified joint law, source coefficient covariance, complete tail evidence or known transport truth. Missing precision stays missing; source mean/SD, estimator uncertainty, seed variability and structural/transport uncertainty remain distinct.

Before any real context execution, the optional adapter additionally needs focused invented-data tests for parent/child binding, context/unit mismatch, whole-cohort no-input behavior, unavailable semantics, tampering, limits and no overwrite. These are interface checks, not a new biomedical pilot.

Allow one revision only after all three initial-seed feedback reports are retained. Give the builder all approved source diagnostics and availability reasons, with source-context and target-proxy labels intact. The builder may retain the initial model; no target effect is returned. Preserve both stages rather than selecting favorable seeds or checks. Do not impose an arbitrary source-loss threshold: successful execution, source fit and target utility are separate outcomes. Report raw item-wise discrepancies and the three-seed spread; do not treat that spread as a clinical confidence interval or pool incomparable units without a separately justified frozen objective.

**Stop this design/admission loop** after one bounded review of already retained estimator/selection metadata: admit a supported item, leave it unavailable, or simplify the feedback claim. If zero checks are executable, numerical source-fit improvement is not a testable claim in this campaign; an approved evidence-to-whole-cohort utility test can still be considered without pretending to have that loop. Stop the case only for a required target measurement/eligibility obstacle, unacceptable exposure, exhausted permitted resources, or failure of the independently reviewed minimal protocol—not merely because distributional assumptions are necessary. Freeze all candidates before the single reference-evaluation stage, run every planned analysis on every planned output, and report failures and unfavorable results. Source fit alone is never the admission outcome for target utility.
