## Initial findings and final resolution

1. **P1 — matching source/recipe unit labels does not bind the actual task measurement.** `_signature` and `_bind_evidence` validate source/recipe/evidence label equality (`:59,95–96`) but never inspect `task.columns[*].unit`, which exists in `contracts.py:98–101`. For example, a source mean and recipe labelled centimetres can be applied directly to a task column declared in metres while the sidecar declares identity measurement. The gate returns `matched_declared` and calculates an unconverted discrepancy. This is a static execution-path finding, not a clinical experiment. Bind every referenced source variable's unit to the task; validate supported statistic output units; reject unknown mappings and unsupported conversions. Coefficient increments/scales need particular care. Agreement remains with declared metadata, not proof of correct source extraction.

2. **P2 — unknown task columns can pass complete-recipe preflight.** `_signature` validates column-name strings but not membership in the task (`:64–83`); `_preflight` only compares declared source and recipe signatures (`:175–181`). A later check with the same nonexistent filter column in both declarations passes preflight. The loop then computes earlier statistics before `apply_operator` rejects that later check (`:217–228`; `source_checks.py:87–100`). The final receipt is not written, so this is not a persisted false result; nevertheless it violates the stated whole-recipe gate before any numeric source operator. Validate source and recipe references against task schema before entering the numeric loop, including recipe references associated with unavailable checks.

**Resolved in the final reviewed version.** `_variables` enumerates all operands, including filtering/event columns (`:94–106`). `_measurement` requires an exact source-variable unit mapping, checks task membership and identity units, validates moment output units and explicit per-unit unstandardized OLS units (`:109–132`). Correlation units are dimensionless (`:89–90`). `_preflight` checks every non-null recipe before the arithmetic loop (`:235–249`), including checks whose eventual semantic result is unavailable.

A related follow-up identified matching source/recipe Boolean predicates and string literals against numeric task columns. The revised `_predicate` rejects Booleans (`:46–48`); `_task_operator` validates predicate scalar/list types against task kinds and requires numerical statistical operands (`:135–152`). This prevents pandas string/numeric comparisons or Boolean/numeric coercion from silently supplying a different event count, and prevents the identified late runtime failures. No conversion is inferred. The code now closes the concrete static counterexamples found in this review.

## Confirmed safeguards and scope

The new collector is an operational gate rather than an unused validator. `_compute` verifies the frozen candidate and the presence of its committed sidecar, runs `_preflight`, verifies a successful linked execution, and only then invokes source operators (`:205–230`). All declared checks require one binding. Role/term/adjustment/filter/event mismatches cannot be excused by `approximate`; supported weight/transform status handling suppresses numeric discrepancies when unavailable. The full recipe is inspected before the loop, subject to the task-schema omission above.

Source uncertainty is carried verbatim into an explicit role; SD cannot become estimator precision (`:114–135`). Missing source n is not replaced with generated `n_used`. MC uncertainty remains explicitly unestimated, and the report calls discrepancies unstandardized. No unsupported uncertainty pooling or claimed calibrated intervals were identified.

The separate folder, exclusive output creation, candidate hash verification and full report recomputation preserve legacy receipts and frozen candidate bytes (`:257–286`). The collector does not import or execute a candidate generator. No new preservation hazard was identified statically. This is not an independent whole-project preservation-hash audit or sandbox audit.

## Residual limitations that must remain explicit

- The adapter verifies consistency of declared semantics. A builder can still mistranscribe the source into both declarations; locators, hashes and approval labels do not establish source truth or population applicability.
- `source_n` is a positive integer plus prose scope, without a structured participants/observations/clusters distinction or statistical compatibility check. It is retained metadata, not independently validated source sample size. Its value is not used for precision calculations.
- The uncertainty structure classifies one legacy uncertainty annotation. It cannot simultaneously represent source estimator SE/CI and individual SD for the same item. SD convention is implicit in the supported operator (`ddof=1`); population-SD or unknown-convention sources must remain unsupported/unresolved rather than being silently relabelled.
- MC estimation, transport uncertainty, weighting, measurement transformations, general source-population reconstruction and statistical authenticity remain outside this unit. Identity unit-label matching is not a measurement ontology or a conversion engine.
- Legacy entrypoints remain callable. Adoption by a new-case controller must be explicit, with no fallback; this unit does not retroactively fix historical collectors or establish new biomedical utility.
