# Method coverage for manuscript v26

Audit date: 9 November 2026. This review reads existing reports, metadata and selected implementation files. It creates no experimental results and changes no frozen artifact. Historical augmentation and temporal prediction are covered only through the existing strengths audit. The companion [JSON ledger](METHOD_COVERAGE.json) contains exact paths, observed hashes and resolved historical code commitments.

**Conclusion: the bounded manuscript needs no new run.** The evidence supports a common scientific procedure implemented in several frozen versions. It does not show that one unchanged current release produced every result. Earlier analytical-use findings remain usable when their input regime, controller, correction and reference status are explicit. Performance across requests with the newest controller is not established.

## Common procedure and implementation boundary

We studied a common procedure through several frozen implementations: an Agent interpreted the admissible evidence, specified a stochastic generative law and its unresolved assumptions, and produced tables for prespecified analyses. Retrieval access, source-check operators, review and revision schedules, and execution controllers were study-specific and are reported separately. Most modern studies sampled records from Agent-authored programs; historical literal-row and augmentation studies used different input and generation modes. Newer adaptive and source-context interfaces were exercised in separate developmental or source-only studies and were not retrospectively used in the earlier experiments.

The common invariant is scientific and procedural: define the analytical request and admissible information; interpret evidence; choose a law and unresolved assumptions; execute or author the declared data representation; check contracts and scientific meaning; select/freeze the candidate; and evaluate using the fixed analysis. It is not a claim that every study exercised every implemented interface. A source-check result, a target-transport result and downstream utility are separate observations.

Several concrete differences prevent an unchanged-release description:

- [The core runner reuse audit](../core_workflow_replication_2026-11-04/RUNNER_REUSE_AUDIT.md) states that main_session_v1 requires zero retrieval budget and snapshots the registry. Open retrieval needs a new append-only registry policy, allocation, family/revision controls, closure and evaluator dimensions.
- evcBuild01 uses a different schema/unit order and delivers three initial tables before the retain/revise decision; retained outputs are aliases. Core instead makes three new final draws after the decision. Its CHNS OLS/sample-SD/linear-quantile provider and ENSANUT equal-cell WLS/population-SD/inverse-CDF-quantile provider are case-specific.
- [Iron execution documentation](../iron_breadth_2026-11-05/EXECUTION.md) explicitly identifies a compact adapter, not the earlier six-author controller or full signed-off semantic-feedback manifests. Sharing the execution worker does not erase this distinction.
- Analytic uptake, approximate checks on target rows, assumption-qualified descriptive differences and separately generated source-context projections are different feedback mechanisms. The latest source replay computes its declared source projections, while all 24 strict semantic checks remain unavailable.

Shared low-level code is genuine but narrower: execution.py, _worker.py, lifecycle.py and semantic_feedback_v1.py have the recorded unchanged hashes in the selected audit. These components do not identify the allocation, information budget, source operators, schedule or analysis of a study. The JSON records the complete four hashes and distinguishes an observed current hash from a manifest-bound historical identity.

The main dispatch records explicitly report an inherited host model with exact backend identity unavailable. The reviewed records do not establish one named language-model backend across all dates. Fresh scientific author counts are not evidence of model-family diversity. The host dispatched authors; the harness did not independently launch an autonomous model. Generator-process isolation is separate from the author's general tool access.
