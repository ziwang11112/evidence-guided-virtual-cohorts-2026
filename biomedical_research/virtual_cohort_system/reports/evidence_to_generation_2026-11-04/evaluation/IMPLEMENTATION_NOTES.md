# Bounded controller and aggregate evaluation

The controller supports only request B. It does not choose scientific parameters, import generator programs, select favorable draws, or execute a local fallback. A single initial candidate and at most one direct revision can be bound. The initial trial uses seed 7400, and all initial deliveries use 7401, 7402 and 7403. The revision trial at seed 7410 is optional, as clarified by the controller task; all revised final deliveries remain mandatory at 7401, 7402 and 7403. At most eight physical attempts are permitted, including failed or interrupted reserved attempts.

Every execution uses the existing reviewed `execution.run_candidate` WSL/bubblewrap adapter. Reservations precede execution. A session lock prevents overlapping controller actions; a hard crash leaves the lock and reserved attempt for explicit audit rather than retry. `semantic_feedback_v1` is called explicitly with no legacy collector fallback. Successful output bindings survive feedback or diagnostic exceptions, which are recorded separately.

Use `run_session.py freeze --request B --candidate NAME` for initial freeze. Use `--parent INITIAL_NAME --revision PATH` for the one permitted revision. Run the fixed stages with `run_session.py run --request B --candidate NAME --stage STAGE`.

Before final delivery the author writes `FINAL_DECISION.json` with `choice` equal to `retain` or `revise`, and `candidate` equal to `candidates/NAME`. Retain final delivery creates three aliases of the initial runs, with no new execution. It cannot follow a revision trial or a different frozen final family.

After author closure, run `evaluation/evaluate_build.py close --initial candidates/INITIAL --final candidates/FINAL --author-closed`. This creates `LIVE_CLOSURE.json` exclusively and binds candidate freezes, the decision, session records, execution receipts, successful delivery tables and the control manifest. Evaluation rejects changed bindings. Run `evaluation/evaluate_build.py evaluate` to create the aggregate reference-read receipt, `REPORT.json` and `RESULTS.md`. These output files are exclusive: a repeated evaluation cannot overwrite an existing report.

The evaluator reads only the historical aggregate `REPORT.json` pinned in the protocol, after closure. It provides no patient-data decoder and does not refit the reference. It compares both prespecified regressions, all coefficients including every nonintercept term, marginals and BMI–HbA1c / glucose–HbA1c Pearson and Spearman correlations. Every scheduled delivery slot remains in the report. Synthetic seed ranges and sample standard deviations are separate from reused real-reference intervals and conditional synthetic HC3-t intervals. No equivalence threshold or composite success score is used.

Internal QR and NumPy consistency checks supplement, and do not replace, the separately assigned reviewer. Unavailable synthetic intervals remain explicitly unavailable; coefficient checks and the delivery slot are retained. Artifact hashes are integrity commitments, not OS isolation, signatures, or evidence of scientific validity.

The latest targeted routing check is `CONTROLLER_MOCK_CHECKS.181098dd30ac.json`; the earlier `CONTROLLER_MOCK_CHECKS.json` is the preserved pre-review check. `ANALYSIS_ROUTING_CHECKS.json` checks only the newly added secondary-analysis route and unavailable-interval handling with an in-memory analytical fixture. Neither check executes a scientific candidate, reads clinical rows, reads target-reference results, or reruns a historical campaign.
