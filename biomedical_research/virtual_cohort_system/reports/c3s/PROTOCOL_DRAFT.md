## Question and scope

Can a fixed, traceable set of heterogeneous published source statistics constrain an Agent-authored whole-cohort generator more effectively through bounded numerical fitting? Does any improvement persist on unused simulation seeds without hiding tradeoffs among the source checks? A source-defensible second structure may test a specific functional-form alternative. ## Numerical experiment

- At most two structures, one locked fitting session per structure, at most 40 objective evaluations including the initial parameter vector.
- Fitting seed 19101, held constant across parameter trials for each source context. Deterministic bounded coordinate search reuses the prior implementation.
- All 20 source constraints occur exactly once, with the author's fixed positive scales/weights and explicit reasons. Optimization loss is a weighted mean of squared scaled differences; it is not a calibrated probability, clinical equivalence measure or universal quality metric.
- Only named top-level scalar parameters may change. Scientific code, source context distributions, source operators, evidence and all unlisted parameters stay fixed. No unreported covariance, domain or source-population composition is optimized without a new prospectively reviewed scientific plan; none is authorized by default.
- Missing/failed/nonfinite checks make a trial infeasible. Keep all attempted trials and failures. Initial selection and the entire trial transcript must precede replay.
- Freeze the selected trial before checking both the initial and selected parameterizations at unused seeds 19111 and 19123. If selected equals initial, reuse identical outputs and count them once. No selection changes after these checks.
- Maximum execution reservation is 88 per structure: 40 trials × 2 contexts, plus baseline/selected × 2 unused seeds × 2 contexts. Maximum unused-seed final tables across two structures is 16, before any identical-output reuse. Trial tables are development intermediates, not independent biological validations.
- Use the existing 30-second, 1,024-MiB, 20-MB-output, 100-KB-log per-execution limits. No new API, training, HPC or automatic scheduler. Do not interpret resource caps as measured usage.
