# Independent controller review before scientific execution

Date: 2026-10-31. Reviewed run_integration.py as text only. No controller, generator, test or retrieval was run. Candidate science review remains pending author completion.

The corrected method now describes enrichment source_replay accurately. The unit controller uses the existing public validation, lifecycle, execution and whole-cohort feedback functions; it adds no scientific law or library module. The seal binds method, plan, prompts, admission, task/source, initial frozen candidate, interface/worker code and host dependency versions. Runtime dependencies are recorded by the actual execution. Exclusive stage-start records and fixed stage names/seeds give the intended two-run, same-seed schedule; recorded failures close the unit. Source outputs remain outside candidate freezes.

Two changes are needed before the first scientific run:

1. Fully check the small supported operator schema in preflight. _read_plan validates metadata, but the current explicit loop still accepts extra operator fields and invalid missing_policy values that apply_operator rejects only after execution. Require exactly kind, unit, selection, missing_policy, column; require missing_policy=error; require each selection to contain exactly column, op, value and integer values; retain the existing exact six-statistic/stratum checks. This is a bounded six-check preflight, not a new general operator validator.
2. Recheck final-decision prerequisites at run('final'). Currently it requires only an initial receipt file's existence and any valid frozen final candidate. Thus a final candidate frozen independently could reach execution without parent linkage or the authentic feedback copy checks in final_freeze(). Require the frozen final receipt to have initial as its parent with revision_index=1; verify the original initial feedback for the expected initial/run; compare the final copy and its checks.json binding; and preserve initial evidence/recipe bytes. Reuse these checks between final_freeze and final execution if convenient.

Other observations are boundaries rather than requested framework changes. verify_assembly checks retained hashes, not cryptographic authenticity against a writer replacing all records. Quotas are independently checked after execution because the native task schema does not express quota counts. Structural failures before any execution may be corrected transparently; generator/feedback failures after the stage-start record may not create a replacement scientific run. Complete final lineage and independent scalar recomputation are still prerequisites for F1 readiness.
