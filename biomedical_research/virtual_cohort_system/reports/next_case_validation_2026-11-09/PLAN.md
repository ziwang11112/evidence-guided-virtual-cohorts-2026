# Next-case admission, fixed-method execution and analysis validation

User authorization: inspect existing data, select a suitable new validation case, freeze the method and evaluation, then run; focus on the core contribution and independently review implementation. This unit starts on 9 November 2026 and follows the v0.27 editorial release.

## Scope

The primary task remains full virtual biomedical cohort generation from a research request, a target-population description and published external evidence. Agent authors choose the scientific structure and parameters. The host supplies workflow, permitted inputs, review and deterministic execution/evaluation. No root-authored target effect, desired direction or target-informed numerical calibration is allowed.

First audit existing local identities, access, study/task history and metadata across the full biomedical_research workspace. Do not inspect candidate clinical values or new target means, correlations or regressions to choose a favorable task. Existing reports can establish what is already exposed. A new endpoint in an exposed study is a qualified prospective task, not a new independent cohort. The admission decision must explicitly choose that label or find a genuinely unexposed reference; it cannot silently switch between the two.

No new dataset acquisition is launched by this initial audit. No old freeze, program, receipt, target or historical protocol is modified. Existing user-accepted data-use agreements persist. Participant tables, generated records and third-party full texts stay local. No new paid API, training, HPC, account, controlled-data application, external message or scheduler.

## Gates

1. **Inventory/admission:** independent history and task-feasibility reviews; verify local file identity, units, population, measurement/selection constraints, prior exposure and access. Nominate one task and a backup using metadata, not outcome quality.
2. **Evidence:** establish adequate external published constraints and explicit remaining joint/transport assumptions. Source-study replays and target analyses are distinct. Target-family evidence cannot be passed off as independent external evidence. Keep exact source provenance and incidental exposure.
3. **Method/evaluation freeze:** record actual Agent service/model metadata as available, prompts/tools/skills, source rules, review gates, seeds, final table size, analysis estimands, diagnostic scope and stopping rules. Review the execution/evaluation code and any genuinely new operator using artificial fixtures before target reveal. Do not repeat passed checks without a code or scope change.
4. **Construction:** up to five fresh-context authors; three predetermined final draws per selected law (15 final tables). Trials and at most one source-driven revision per author are separately logged; retain is valid. All complete/failed authors and outputs are included. Final evidence/method boundaries must be fixed before author dispatch. Do not send target outcomes/results or old target-fitted programs.
5. **Seal/evaluate:** close all author choices and bind every generator/output, then evaluate all prespecified analyses against the selected real reference. Independently recompute key estimates. Keep all adverse outcomes; do not regenerate to improve revealed results.
6. **Report:** show scientific estimates, reference uncertainty, author variability, within-law variation, necessary dispersion/dependence checks, costs and limitations. Neither rows nor seeds count as independent clinical replications. Synchronize only reviewed original code/docs/metadata/aggregates if the unit completes.

## Stop and fallback

If no candidate can be defensibly admitted from existing data, preserve the admission failure with exact reasons and the smallest missing resource. Do not automatically replace it with an exposed target rerun or expand downloads. If a qualified new task in an exposed cohort is feasible, report the narrower evidence role before claiming success; root must record the independent admission rationale. If source evidence does not constrain a requested analysis, distinguish assumption-dependent generation from supported validation rather than inventing a coefficient or a passing threshold.

This plan is the workflow boundary, not the case-specific frozen scientific protocol. The case-specific freeze requires admission and implementation review first.
