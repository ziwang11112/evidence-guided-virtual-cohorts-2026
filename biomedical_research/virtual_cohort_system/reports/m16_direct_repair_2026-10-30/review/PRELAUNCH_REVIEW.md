## Design and implementation findings

1. The protocol fixes three constructions, two possible revisions, all initial/final results and 24 target estimands. It distinguishes one shared target cohort from three construction repeats and avoids required superiority over another Agent.
2. Builders are fresh-context agents, given their own bundle and allowed interfaces; no previous result or desired scientific coefficient is supplied. Starting sources, covariates and budgets are shared. Unique task IDs for literature-session binding are legitimate; all other task semantics must match.
3. `precommit` requires absence of generated rows/freeze and binds evidence, model, construction and revision plan. The exact construction is also embedded in model parameters, preventing divergent prose and machine-readable expectations. A canonical receipt is copied into the later frozen candidate.
4. The initial stage requires the initial action and no parent. A later stage rejects the initial action. A final stage cannot bypass an already committed revision1. A terminal final freeze closes further nonterminal feedback and construction.
5. The source-check plan is now committed inside model parameters. Source recipe definitions at freeze must match that plan, except for their later table binding. This repairs the initial gap where source checks could have been selected after seeing authored rows.
6. Row repair and retention preserve the declared model/construction. Retention additionally preserves evidence and generated bytes. Changed declarations are model revisions, not merely better realization of unchanged assumptions. Every noninitial candidate binds its actual parent's feedback.
7. Feedback reservations are exclusive and recorded before computation. Direct execution validates supplied tables with `generator_executed == false`. It does not populate urate. Source checks plus current and original construction diagnostics are retained; no target-reader exists in controller feedback.
8. Source mismatch remains a diagnostic under population/measurement assumptions, not a mandate to force equality. Working guides and conditional moments are differentiated. No exact residual-zero constraint or favorable candidate selector is implemented.
9. `commit_prelaunch.py` binds protocol, controller, builder-facing instructions, admission records, all three task/X/session/source files, seed registry prefixes, relevant engines and evaluator. It records the reference hash from safe custody metadata without opening its content. The script refuses an existing prelaunch record or pre-existing builder candidate output.
10. The evaluator checks the prelaunch bindings, seed registry prefixes, per-builder task/X membership, canonical preauthoring receipts and copied bindings, initial/final lifecycle freezes and any revision1 ancestor before opening the reference. The released reference path/hash/weight-column metadata must equal the pre-generation commitment.
11. Each candidate is paired to the identical reference IDs, order and X. All comparisons and all improvement/degradation records are kept. A documented failed construction stays scheduled and is not silently replaced. Reference bytes are loaded once after release; the fixed numerical module is unchanged.

## Remaining procedural limits

- These tools do not create an OS sandbox. Audit hashes prove file identity, not that a model never saw other data or that a recorded scientific assertion is true.
- Pre-authoring timestamps and file absence record visible artifact chronology. They do not prove private model cognition or independence of repeated LLM behavior.
- Provenance and comparability need actual scientific review for each submitted construction; schema validity alone is insufficient.
- Evidence lacks universal identification of all conditional relations. Self-consistency success is not biological validation, and a retained unsupported relationship must remain labeled as such.
- The self-check module has a separate passing independent review, including 477 independent arithmetic comparisons and controller guard/stop branch checks. Its current tests/review must be bound in prelaunch before launch; this protocol review does not substitute for that numerical verification.
- A fresh target cycle is not proof of absence from model training. The old exposed target remains closed.

## Final bounded update before launch

The controller's final action gate excludes `stop` from candidate precommit. A scientific/operational stop is recorded in a separate `stop_record.json`, retaining any valid initial table as a scheduled failed construction; it is not coerced into a lifecycle `revise` freeze. An unchanged submitted final table uses `retain`. The builder instructions now explicitly document this distinction and disclose target-cycle/assay/selection metadata without target values. These are the only follow-up changes to the controller/instructions reviewed here; the evaluator and numerical estimands remain unchanged.
