# Research-demand-driven biomedical data generation

Latest user direction, 3 November 2026: the primary product is useful generated data. Give the scientific Agent enough room to understand the intended analysis, retrieve evidence, choose a construction, run numerical checks and revise it. A single unchanged generator across different research requests is not required. This prospective scope supersedes narrower general-method wording in earlier design notes; it does not rewrite frozen experiments or claim new capabilities have already been implemented.

## Product and Agent freedom

The user supplies a research purpose, population, desired variables, intended analyses and any available observations. Analysis questions are visible to the Agent. The Agent can clarify material ambiguities or proceed with explicit reasonable assumptions. Whole-cohort synthesis without individual input, unmeasured-variable enrichment and missing-cell completion remain supported research goals.

The reusable object is the system's evidence-to-data procedure. Its particular generator can change by task, population, measurement and intended use. The Agent may choose direct row output, a stochastic program or a hybrid route; choose scientific structure, dependence, margins and parameters; search and re-examine relevant original studies; simulate proposed constructions; use numerical tools; and revise structure as well as parameters. A source-informed decision is not required to be a hand-derived closed-form solution. No particular family, sign, interaction, architecture, Agent count or training stage is imposed as the method's identity.

Approved literature access should mean access within the research scope and existing resource limits, not that the coordinator must pre-extract every usable result. Relevant evidence with incomplete or differing conditions remains visible with qualifications. Missing evidence can motivate a stated assumption or sensitivity scenario; it does not automatically prohibit exploratory data generation. An unsupported assumption must not be described as a measured biological fact.

Ordinary retrieval, source-side trials and revisions within an agreed work unit do not each need a permission question. Resource bounds prevent indefinite work; they should not recreate the old blanket ban on numerical trials or limit every task to one static retain/revise decision. Existing restrictions on new paid APIs, training/HPC, data access agreements and disclosure remain unchanged.

## Lightweight working loop

1. Understand the requested data and analysis use.
2. Retrieve and organize relevant evidence, including unresolved applicability and dependence.
3. Construct a candidate data-generation approach.
4. Generate working data and inspect scientific relationships, distributions and relevant source checks with tools.
5. Revise as needed, retain useful alternatives or state an unresolved limitation.
6. Deliver the data with a concise source/assumption record and what its analyses can support.

Version the submitted artifacts and retain consequential revisions and failures. Do not require a large administrative review package for every exploratory numerical operation. Use the existing safe execution facilities where available; this design note does not create an implemented optimizer, literature adapter or new controller.

## Reference information can be used; distinguish its roles

The Agent can know that the requested analysis is, for example, an age/sex-adjusted BMI–insulin regression. It may use published evidence, authorized real observations, reference distributions and analytical feedback to construct and revise the data. There is no universal rule that real measurements or reference results must be hidden. Source-only/no-individual-input generation is one explicitly labelled information regime, not a compulsory restriction on every request. Full-reference-informed generation is a different valid regime.

Withholding applies only to information reserved for an independent evaluation of that delivered version. Declared observed inputs remain available for enrichment or completion. A reference statistic can be returned as developmental feedback when the task permits it; its subsequent agreement then measures calibration to that feedback rather than an independent prediction. Record the transition and preserve the earlier version/results. A new research request or development version may use a different generator.

If retrieval exposes a target study's answer, record that exposure. That information can support a separately labelled reconstruction/development task, but agreement with it is not an independent test. Likewise, source statistics used to construct the data are legitimate inputs; reproducing them measures source consistency. Neither situation requires hiding the research question.

Whole-cohort synthesis has no one-to-one patient ground-truth table. Real cohorts are sampled reference distributions with measurement and selection limitations. Masking genuinely observed measurements for a completion experiment provides a controlled reference for that particular task; it does not mean every virtual person has a recoverable real counterpart. Even with no untouched reference, source fit, numerical validity and use-specific consistency can be evaluated. Claims about unseen populations or previously unchecked relationships remain unestablished in that setting.

Different real datasets can provide distributional and analytical comparators. Define the intended population and check measurement units/methods, age and sex composition, eligibility, treatment/health status and study period before interpreting discrepancies. Use appropriate stratification, standardization or separately reported conditional analyses when justified and when covariate support permits them. Alignment does not remove all transport uncertainty. Do not expect an intentionally different scenario to reproduce every raw comparator distribution; state what should remain comparable.

Evaluate marginal distributions, the joint/conditional relationships needed for the requested science, and the resulting analyses. Identical individual-variable distributions do not imply correct joint relationships. Multiple real comparators help describe heterogeneity; they are not automatically independent corroboration if their results already guided generation. The basic distinction is calibration/reference consistency versus external evaluation, not whether a perfect ground truth exists. Existing datasets, appropriate held-out portions or unused study waves may support these roles; this amendment requires no fixed number of cohorts or new data acquisition.

Same-table multi-analysis reuse is an optional additional capability. It is required only when that particular request or paper claim promises such reuse. Future primary evaluation can instead measure whether the same adaptive system delivers useful data for several declared requests. Freeze each delivered request/version for its evaluation, not one generator forever. A claimed improvement over another method still requires an appropriate information/resource comparison; ordinary feasibility does not require superiority to another Agent.

Judge analysis usefulness with meaningful effect scale and uncertainty, supported by the distribution checks that the use needs. Exact agreement with one real sample is not required. Unsupported variables, hypothetical populations and untested analyses remain described as such. More generated rows are additional realizations of the model, not additional measured participants.

## Immediate project consequences

The proposed information-provision and feedback-revision experiment (a local historical design, not included in this export) turns reference-access choices into controlled comparisons while keeping evaluation roles distinct. Its optional four cells do not restrict the deployed system's scientific freedom or launch new runs.

- Keep the completed 3 November A01/A02 continuation and all prior revealed studies closed and unchanged.
- Treat the old fixed packet, static-only authoring, one-decision branches and identical-byte source bridge as conditions of those experiments, not universal constraints on this system.
- Make a future author task explicitly disclose research purpose and allow scoped retrieval, numerical source checks and scientific revision. Audit actual tool availability before claiming that these freedoms are operational.
- Keep Pro's proposed sampling diagnostic as a bounded evaluation-support option. It is not the project objective and is not a universal prerequisite for every future data-generation task.
- Do not restart an old allocation, enlarge exhausted quotas, launch a new campaign or change a schedule through this scope document. The next bounded work unit should implement the smallest missing capability needed to generate useful data under this corrected scope, using existing data and tools where possible.

The intended contribution remains biomedical data generation from fragmented published evidence. Task adaptation is a useful system capability; its scientific value must be demonstrated in the resulting data and analyses, rather than inferred from the presence of an interactive interface or extra Agents.
