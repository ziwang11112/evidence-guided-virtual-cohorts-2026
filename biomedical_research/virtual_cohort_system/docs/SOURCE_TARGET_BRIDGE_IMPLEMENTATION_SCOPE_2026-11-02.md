# Source/target bridge: bounded implementation scope

2 November 2026. The user approved continuing under [design v1](METHOD_AND_EXPERIMENT_DESIGN_v1_2026-11-02.md), first connecting the source and target generation flow, independently reviewing the implementation, then proceeding according to the frozen experiment. This scope fixes the next implementation unit before a live fixture run. It does not release a clinical case or alter the existing campaign.

## Connection to implement

- One frozen Agent-authored scientific construction contains every source and target context and the assumptions about what is shared or context-dependent.
- Source and target child executions use identical generator bytes and the same scientific specification except the explicit `active_context` selector. Fixed context tasks may differ in population and row count, not silently in variable identity or canonical units.
- Deriving task/specification/semantic hashes does not create an independent scientific review. Preparation emits review requests; a separate actual reviewer supplies the required commitments before sealing and executing.
- Source feedback explicitly uses `semantic_feedback_v1`; a declared supplemental policy can also use the reviewed geometric-mean/prevalence collector. No legacy feedback fallback. Target executions need output validation and linkage; they need not invent a source comparison when none is declared.
- A finite list of trial IDs, contexts, row counts and seeds is frozen in the parent. Each attempt is recorded before dispatch and consumes its slot even if execution fails. A canonical preparation destination prevents a new directory from silently resetting that candidate's budget. The global campaign controller still governs aggregate clinical construction budgets.
- Verification binds actual source and target execution receipts and outputs. Common bytes are mechanical linkage, not proof that a generator implements a scientifically valid transport rule, that an Agent authored it, or that the host cannot coherently rewrite all records.

## Unit handling

Generation uses one canonical unit per variable across contexts. A separate, explicit, reviewed positive multiplicative mapping can convert a verified generated target frame into analysis units. It preserves row identity and other columns and records input/output content digests plus caller-provided execution commitments. The conversion component is pure and cannot itself authenticate those caller commitments; the integration caller must verify the corresponding execution first.

This is not general mixed-unit source feedback. The existing collectors require source and generated-task units to match. Choosing source-native canonical units can support the current lipid route; the target analysis can use a separately converted view. Different source units, nonlinear conversions, assay/specimen harmonization, derived non-HDL feedback and parameter calibration are not automatically supplied by this adapter. A numerical unit factor never establishes equivalent assays or fasting conditions.

No production clinical conversion constant is activated solely from model memory. Any clinical mapping requires a documented unit reference and its own declared contract. Invented fixtures use explicitly invented units/factors, never interpreted as clinical evidence.

## Review and actual smoke scope

Implementation tests use invented arrays and frozen invented bundles. Old passing suites are not rerun. After independent implementation review, the root coordinator will use the existing inspected WSL/bubblewrap backend for a single source/target fixture pair. The exact fixture task, seeds, row counts, source diagnostic and unit map must be fixed and reviewed before launch. The fixture contains no patient data or real biomedical relationships. Runtime availability has been inspected; availability is not yet a successful generator run.

The live pair must demonstrate actual freeze -> derivation -> independent binding review -> seal -> isolated source/target execution -> source semantic/supplemental feedback -> joint verification -> explicit target-unit view. Failed attempts remain recorded. Any implementation repair and rerun must have a new explicit software-test record; it must not silently overwrite the first attempt or become another clinical scientific construction.

Expected failure-path checks include changed common scientific parameters, changed generator bytes, wrong contexts or units, missing/forged review commitments, altered output/feedback, duplicate attempts and budget resetting. These are software checks, not a new mechanism experiment or biomedical validation.

## Unchanged scientific boundaries

The root does not fill in target means, desired associations, slopes, residual scales or empirical distributions. Clinical scientific choices remain the constructing Agent's responsibility under the approved evidence packet. Software fixtures contain declared artificial values solely to test transport and arithmetic.

The current campaign still requires case admission, shared evidence, statistical reference specifications, interpretation rules and its global freeze before clinical execution. No patient target is opened by this unit. No evidence search quota, downloads, paid API, training, HPC or scheduler is expanded. Passing this implementation checkpoint establishes a working connection within its supported scope, not superior generation quality.
