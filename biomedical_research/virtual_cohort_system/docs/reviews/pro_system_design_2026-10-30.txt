系统最重要的能力应当是：**把一篇论文中的结果，正确转换为生成器可以执行的约束；发现约束无法满足时，判断应该修正解释、重新拟合、修改结构，还是承认信息不足。**

## 一、这个方向现在最应该明确的，是三个不同层次

你的总问题定义可以保持不变：

> 将发表文献中分散的证据，转化为可复用的虚拟生物医学数据，缓解真实数据与指标不足，并验证这些数据能够支持哪些科学分析。

但研究推进时，最好把三个层次分别说清楚。

### 1. 应用层：我们要交付什么

交付的是：

- 可以使用的虚拟或增补数据；
- 能重复生成这些数据的程序与参数；
- 这些数据所依据的文献证据和假设；
- 对其科学分析用途的验证结果。

对于第一个整列增补场景，输入可以是一个只有年龄、性别、BMI、血糖等变量的真实队列，输出是在保留原有记录的基础上增加一个虚拟指标。

这里有一个范围需要明确：**首阶段生成的是个体级分析表。** 如果以后要生成测序 reads、原始影像或仪器信号，还需要相应的测量过程模型，当前表格增补的验证不能自动覆盖那些任务。

### 2. 方法层：系统到底做了什么科学工作

方法层的核心问题是：

> 不同论文报告的不同统计量，怎样共同约束一个能够应用于目标人群的生成机制？

这比“让 Agent 看论文然后生成 CSV”具体得多，也更容易检验。

例如，系统需要处理：

- 一篇论文报告总体均值；
- 一篇报告男女分层中位数；
- 一篇报告调整年龄后的 BMI 斜率；
- 一篇报告调整年龄、肾功能和生活方式后的 BMI 斜率。

这些结果的统计含义不同。系统必须理解它们分别在约束什么，不能将它们直接混成同一组模型参数。

### 3. 评价层：怎样证明生成的数据有用

你已经提出的三层证据链是正确的：

1. **来源证据使用正确。**
2. **独立真实队列中的科学关系得到有用的保留。**
3. **同一冻结生成器能够支持多项后续分析。**

我建议增加一个明确要求：**成功和失败都要对应具体分析。**

例如，可以得到这样的结果：

> 年龄主效应和 BMI 平均关联得到支持；性别分组斜率仍主要由假设决定；尾部比例对跨人群基线迁移很敏感。

这已经是有价值的研究结果。它比笼统地把整张表判定为“真实”更有信息量。

## 二、真正的科学难点，是从“发表结果”走到“个体生成机制”

### 1. 文献中的统计量通常不能直接成为生成参数

假设生成器采用：

\[
Y=\alpha+\beta X+\varepsilon.
\]

论文报告的总体均值，并不直接等于 \(\alpha\)。总体均值还取决于来源人群的 \(X\) 分布。

如果模型非线性：

\[
Y=f(X)+\varepsilon,
\]

那么“将平均 \(X\) 代入模型”通常也不等于“模型在整个人群中的平均结果”。

类似的问题还有：

| 文献报告 | 系统应当做的事情 |
|---|---|
| 总体均值和标准差 | 在来源人口中生成数据，再计算相同统计量 |
| 男女中位数 | 重现来源分层，再计算组内中位数 |
| Pearson 或 Spearman 相关 | 按照原变量尺度和变换，计算相同相关统计 |
| 调整后回归系数 | 在模拟来源数据中拟合同样的回归公式、调整集和权重 |
| 阈值以上比例 | 在相同单位、测量条件和选择条件下计算比例 |
| 纵向变化关系 | 使用相应时间结构，不能直接当作同期横断面关系 |

因此，我建议把方法的中心对象定义为：

> **来源分析算子：在来源研究条件下，对生成数据执行该论文所报告的分析。**

这一步让“使用文献”成为可以检查的数值过程。

### 2. 来源人口与目标人口必须分开

设目标队列只有可见协变量：

\[
D_T^X=\{x_i\}_{i=1}^{n_T}.
\]

第 \(s\) 篇论文报告统计量 \(\widehat t_s\)，并有对应的来源人口、测量方式和分析条件 \(\nu_s\)。

我们希望构建生成器 \(G_{\lambda,\theta}\)，使：

\[
\widehat t_s
\approx
T_s\!\left(G_{\lambda,\theta},\nu_s\right).
\]

这里：

- \(\lambda\)：生成结构；
- \(\theta\)：可拟合参数；
- \(T_s\)：来源分析算子；
- \(\nu_s\)：来源上下文。

完成来源校准后，才将同一生成器应用于目标 \(X\)。

利用来源协变量分布连接个体模型与汇总证据，已有明确的统计研究基础，例如 ML-NMR。因此，这部分应当建立在已有方法之上，再检验自动处理异质文献证据的具体贡献。[PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC7362893/?utm_source=chatgpt.com)

### 3. 目标的绝对水平需要明确的迁移依据

这是一个很容易被系统设计掩盖的问题。

如果每篇来源都有一个任意的“研究偏移”，同时目标队列完全没有 \(Y\)，那么即使所有来源都拟合得很好，**目标的绝对均值仍可能无法确定。**

首版至少需要明确采用以下一种处理：

- 选取一个兼容来源作为参考，并声明其条件关系或基线向目标迁移；
- 使用有依据的测量转换；
- 保留若干明确的基线迁移情景。

不能只增加自由的 study effect，就认为解决了跨人群迁移。

同样，**单位换算、检测平台校准、人口迁移是三个不同问题**。把 μmol/L 换成 mg/dL，不代表消除了不同国家、年龄结构和选择标准带来的差异。

### 4. 某些关系吻合，不能推出所有后续关系都正确

假设我们只构建了：

\[
Y\mid \text{年龄、性别、BMI}.
\]

之后用户想研究 \(Y\) 与疾病结局 \(Z\) 的关系。如果系统从未获得 \(Y\) 与 \(Z\) 的联合信息，那么生成时独立抽取的残差，可能自动施加一个条件独立假设。

统计匹配研究明确说明：没有共同观测的信息时，一些联合关系不能由现有数据识别；合成补充所采用的条件独立假设，会直接决定相应关系。[www150.statcan.gc.ca](https://www150.statcan.gc.ca/n1/pub/12-001-x/2016001/article/14539/02-eng.htm?utm_source=chatgpt.com)

所以，“可复用”的合理含义是：

> **一个冻结生成器，在明确的证据与假设范围内，支持多项科学分析。**

这也意味着，以后增补多个指标时，不能默认每列独立生成就足够。

## 三、技术创新应该集中在哪里

我建议先集中一个主要方法问题：

> **将具有不同人口、测量和调整条件的发表统计量，转换成可执行的生成约束，并据此构建可复用生成器。**

其他机制围绕它展开。

| 候选贡献 | 我建议的优先级 | 要证明什么 |
|---|---:|---|
| 正确转译不同来源统计量 | 第一优先 | 能避免具体统计语义错误，并改善生成或分析表现 |
| 根据来源失配进行科学修订 | 第二优先 | 修改确实由证据触发，且产生可解释的改善 |
| 根据分析分歧定向寻找缺失证据 | 后续增强 | 找到的信息确实约束了关键未知部分 |
| 保留多种相容解释并传播敏感性 | 配套能力，可继续深化 | 能展示哪些结论依赖哪些假设 |
| 多 Agent 分工 | 按工程需要选择 | 是否改善效率或错误发现，而非默认成为论文主线 |

这里必须正视已有工作：G-Sim 已经有 LLM 设计模拟器结构、数值校准以及反馈修订。因此，**“Agent 写代码＋优化器拟合＋反思修改”本身不足以承担新颖性主张。**[proceedings.mlr.press](https://proceedings.mlr.press/v267/holt25b.html?utm_source=chatgpt.com)

你们更值得深入的地方，是发表证据转译中的具体困难：调整集不一致、来源协变量不完整、边际与条件统计混淆、测量条件不同，以及这些问题怎样影响生成数据的下游用途。

这些是**值得验证的贡献方向**，现在不能全部写成已实现创新。

## 四、具体 Agent system：一个主 Agent，四类确定性能力

### 1. 推荐架构

```mermaid
flowchart TD
    I["任务、可见协变量、来源文献"] --> C["Controller：流程、版本与预算"]
    C --> A["科学 Agent：解释、建模与修订"]
    A --> E["证据卡与来源分析算子"]
    E --> F["数值校准与来源重放"]
    F --> D{"诊断与下一步"}
    D -->|"解释或结构需修改"| A
    D -->|"缺少具体证据"| R["定向检索"]
    R --> E
    D -->|"保留候选"| B["冻结生成器与情景"]
    B --> G["生成增补数据"]
    G --> V["独立真实数据评价"]
    B --> V
```

图中的独立评价只在研究验证时存在。评价结果不返回同一确认案例的构建循环。

### 2. 各组件的职责

| 组件 | 负责什么 | 主要产物 |
|---|---|---|
| **Controller** | 状态、工具权限、预算、版本、冻结和恢复 | 运行记录、发布包 |
| **科学 Agent** | 解释文献、选择模型、说明假设、提出修订 | 证据解释、模型规格、科学决定 |
| **统计工具** | 来源重建、算子执行、参数拟合、重放和敏感性分析 | 可重复的数值结果 |
| **可选复核调用** | 检查明确的语义错误或迁移问题 | 有原文定位的问题清单 |
| **独立 evaluator** | 对真实与生成数据执行相同分析 | 外部科学表现 |

**Agent 负责解释和选择；数值拟合交给程序完成。**

同一个 Agent 可以在不同阶段使用不同提示词：

- 读文献时，要求忠实提取和解释；
- 建模时，要求结构与证据、假设一一对应；
- 修订时，要求指出具体失配及预期影响。

无需预先拆成多个常驻 Agent。额外复核应当针对具体风险，例如“这项边际中位数是否被错误用于条件模型”。

## 五、系统要围绕哪些数据对象运行

我建议最少建立下面这些对象。

| 对象 | 必须保存的内容 | 为什么需要 |
|---|---|---|
| `TaskSpec` | 任务模式、可见变量、待生成变量、人口、时间、用途、预算 | 明确这次生成究竟解决什么问题 |
| `EvidenceCard` | 原文定位、统计定义、数值、单位、调整集、人口、测量、不确定性 | 防止只保存脱离上下文的数字 |
| `SourceContextSpec` | 来源协变量分布、纳入条件、已知信息和重建假设 | 防止用目标人口冒充来源人口 |
| `AnalysisOperator` | 筛选、变换、编码、统计公式、权重 | 让发表结果成为可执行约束 |
| `GeneratorSpec` | 模型结构、参数、分布、适用范围 | 形成可运行生成器 |
| `AssumptionRecord` | 未知部分、采用选择、替代情景、影响分析 | 区分证据和假设 |
| `CalibrationSession` | 固定结构下的参数空间、目标函数、随机方案和预算 | 使数值拟合独立、可复现 |
| `ScientificPatch` | 什么问题触发什么改变、预计影响什么统计 | 记录真正的科学修订 |
| `ReleaseBundle` | 最终代码、参数、证据、情景和生成计划 | 支持冻结与复用 |

其中，**参数来源必须分成四类**：

```text
reported    文献直接报告
derived     由明确公式转换
calibrated  通过来源约束拟合
assumed     当前信息不足，采用假设
```

“文献没有报告交互作用”和“交互作用等于零”需要保存成不同事实。

某个候选为了简化而暂时省略交互，可以接受；但它应当被记录为结构假设。

## 六、具体生成算法应该怎样运行

### 第一步：证据准入

Agent 读完一篇论文后，不能立即将所有数字投入校准。

每条证据应归入四种用途之一：

1. **数值校准**：定义清楚，条件能够重现。
2. **来源检查**：预留检查，不直接用于拟合。
3. **定性结构线索**：提示某种形状或分层，但不能直接提供数值约束。
4. **暂不使用**：关键定义或条件不足。

例如，来源报告调整了肾功能、饮酒和药物使用后的 BMI 系数，而当前生成模型只有年龄、性别、BMI，那么这条系数需要进一步处理，不能直接复制。

### 第二步：建立来源上下文

优先使用发表的：

- 分层比例；
- 协变量边缘分布；
- 已报告的联合统计；
- 纳入和排除标准。

没有报告的相关结构，应保留为显式假设或情景。

这里有一个原则：**优化器不能为了降低来源误差，随意改变未受约束的来源人口结构。** 否则，系统可能通过改变来源假设而“解释”任何结果。

### 第三步：提出少量可解释的生成结构

首版可以从一个连续指标开始：

\[
h(Y)=m_{\lambda,\theta}(X)+\sigma_{\lambda,\theta}(X)\varepsilon.
\]

其中：

- \(h\)：原尺度、log 等适当变换；
- \(m\)：均值结构；
- \(\sigma\)：残差结构；
- \(\lambda\)：线性、低自由度曲线、分组斜率等结构选择。

建议先提供小型通用模板库。模板面向变量类型和函数结构，不固定成某个指标的专用公式。

例如：

```text
位置：
  截距
  连续变量线性项
  低自由度平滑项
  分类变量主效应
  有依据的分组斜率

残差：
  简单同方差
  有证据时增加分组方差或异方差
```

### 第四步：数值校准

对每条来源统计，计算：

\[
r_{sk}(\theta)=
\frac{
T_{sk}(G_{\lambda,\theta},\nu_s)-\widehat t_{sk}
}{
a_{sk}
}.
\]

\(a_{sk}\) 是事前规定的尺度，可以来自来源标准误，或有明确单位的拟合容限。

校准器寻找能够减小这些差异的参数，同时检查关键约束是否分别得到满足。

有几个实现细节很重要：

- 同一研究中的多个统计量，不能默认独立。
- 不能用生成样本量计算一个很小的标准误，冒充来源证据精度。
- 来源内归一化的损失函数可以帮助计算，但不能自动当成统计似然。
- 拟合时可固定随机数，减少目标函数抖动；拟合后用新的随机数重放。
- 总损失低，不足以掩盖某项关键联合关系的严重失配。

### 第五步：诊断，并选择下一动作

Agent 收到数值报告后，应当选择具体动作。

| 发现的问题 | 下一动作 |
|---|---|
| 数值、单位、符号或“每 SD”定义错误 | 重新核查原文 |
| 变换、调整集或分层映射错误 | 修正分析算子 |
| 固定结构能够表达，但参数未拟合好 | 重新校准 |
| 候选结构无法同时满足关键来源约束 | 提出有依据的结构修改 |
| 来源协变量关系未知 | 补证或增加明确情景 |
| 多种相容模型给出不同分析结果 | 定向补证或保留假设敏感性 |
| 缺少必要联合信息 | 限定该分析的支持范围 |
| 没有具体修改依据或预算耗尽 | 保留现状并停止 |

这一步应输出简短、可核查的决策依据，例如：

> 来源 E12 的分层斜率无法由共同斜率结构表达；增加分组斜率项，重新校准，并检查原有边际分布是否退化。

如果没有发生科学修改，就如实记录保留。没有必要为了显示 Agent “会反思”而强行修改模型。

### 第六步：冻结，再生成

冻结对象应包含：

- 生成代码；
- 参数；
- 使用的证据；
- 来源上下文；
- 测量与迁移假设；
- 随机化计划。

之后，同一发布包用于所有预定分析。看到某项真实结果以后再改生成器，应当形成新的开发版本，不能继续被当成同一次独立验证。

## 七、证据不足时，系统究竟应该怎么做

我赞成你提出的“保留合理的多种可能”，但要给它一个准确的实现方式。

### 1. 区分情景变化与残差变化

建议每张生成表记录：

```text
hypothesis_id
source_context_scenario_id
transport_scenario_id
parameter_draw_id
residual_seed
```

这些层次分别表示：

- 模型结构不同；
- 来源人口重建假设不同；
- 迁移假设不同；
- 有依据的参数变化；
- 固定上述条件后的个体随机取值不同。

**增加残差种子，不能解决模型结构或迁移关系未知。**

### 2. 多个相容候选可以并列交付

例如，两个生成器都能满足当前来源统计，但它们对某个分组关系的预测不同。

此时可以：

- 在同一个目标 \(X\) 上生成各自的数据；
- 对每个情景执行同一分析；
- 展示哪些分析稳定、哪些分析随假设改变。

但这些情景之间的范围，不能未经依据就叫作“95% 可信区间”；也不能把全部情景的行拼起来，形成一个看似更大的样本。

### 3. 定向补证应由具体分歧触发

假设差异主要来自 sex×BMI：

- 再找到几篇男女均值不同的论文，可能没有解决问题；
- 找到相同调整条件下的男女 BMI 斜率，才可能真正约束它。

因此，补证请求应写成：

> 寻找能够约束某个未确定关系的统计量。

检索词不应预设希望获得的效应方向。

这个机制可以逐步发展，但首版先实现清楚的“分歧—缺口—检索—重新准入—重新校准”链条即可。

## 八、对照现有仓库，我建议具体改哪些地方

我核查的固定版本中，已经有任务契约、生成执行、来源重放、候选冻结和部分来源检查，因此可以增量扩展。具体代码依据见 [系统 README](https://github.com/ziwang11112/evidence-guided-virtual-cohorts-2026/blob/d33d0cbad4c199fe5b450688fe8050d72afd9861/biomedical_research/virtual_cohort_system/README.md)。

保留现有核心接口：

```python
generate(observed, spec, seed) -> pandas.DataFrame
```

以及原模式名：

```text
enrichment
completion
whole_cohort
```

### 优先修正一：分开来源和目标的人口契约

现有 `source_replay._input_task` 会复制目标 task，再修改 population 和 n_rows。来源输入仍继承目标的部分变量范围和契约。

这会带来具体问题：来源研究如果覆盖更高年龄，可能因为目标年龄上限而无法忠实重放。

应增加独立的 `SourceContextSpec`，分别管理：

- 来源纳入条件；
- 目标纳入条件；
- 生成模型的计算定义域。

不能静默裁剪来源，也不应通过放宽目标范围解决这一问题。依据见 [source_replay.py](https://github.com/ziwang11112/evidence-guided-virtual-cohorts-2026/blob/d33d0cbad4c199fe5b450688fe8050d72afd9861/biomedical_research/virtual_cohort_system/cohort_harness/source_replay.py)。

### 优先修正二：让数值校准拥有独立会话

现有执行接口要求冻结候选。修改参数会使原冻结失效，而正式候选还受 revision 预算限制。

因此，需要新增 `CalibrationSession`：

```text
锁定模型结构
锁定可调参数及边界
锁定来源与分析算子
锁定损失函数
锁定随机化计划
锁定数值预算
执行内部参数试探
物化最终参数
创建新的正式候选并冻结
```

**数值优化中的一次参数试探，不等于一次科学结构修订。**

反过来，扩大参数范围、改变来源上下文、移除冲突证据或更换分析定义，都应产生新的科学记录与校准会话。现有冻结与执行约束可在 [lifecycle.py](https://github.com/ziwang11112/evidence-guided-virtual-cohorts-2026/blob/d33d0cbad4c199fe5b450688fe8050d72afd9861/biomedical_research/virtual_cohort_system/cohort_harness/lifecycle.py) 和 [execution.py](https://github.com/ziwang11112/evidence-guided-virtual-cohorts-2026/blob/d33d0cbad4c199fe5b450688fe8050d72afd9861/biomedical_research/virtual_cohort_system/cohort_harness/execution.py) 中核查。

### 建议的增量目录

```text
agent_runtime/
  runner.py
  actions.py
  state.py
  provider.py

cohort_harness/
  evidence_semantics.py
  source_context.py
  analysis_operators.py
  calibration.py
  sensitivity.py
  release.py
```

这是建议新增的结构。

原有严格 schema 不宜直接塞入新字段。可以使用新版本外层包与 sidecar，但每个 sidecar 都必须有 validator；仅记录 hash，只能证明文件未变，不能证明科学定义正确。

## 九、下一个完整实例：我建议优先筛选“尿酸整列增补”

我已经核查了一个具体候选：

> **使用 NHANES 2017–2018 的可见协变量，依据外部发表证据增补血清尿酸。**

官方 BIOPRO_J 文档包含尿酸变量 `LBXSUA`，以及对应 SI 单位变量 `LBDSUASI`。实际构建时应同时屏蔽两者和直接派生的标签。[wwwn.cdc.gov](https://wwwn.cdc.gov/Nchs/Data/Nhanes/Public/2017/DataFiles/BIOPRO_J.htm?utm_source=chatgpt.com)

**当前状态只是候选。** 本轮没有分析其个体目标数据；项目归档的初步检查未发现既往尿酸任务，但未覆盖全部分支、历史会话和未归档探索，所以还不能认证它是完全未接触的新验证任务。

### 1. Agent 收到什么

起始可见变量可以是：

```text
年龄
性别
BMI
参与者标识
应当保留的抽样设计字段
```

年龄范围与纳入标准在来源准入完成后确定。

来源材料目前至少有两类：

- 韩国一般人群研究，报告年龄、性别相关的尿酸分布，可作为分布和分层统计的候选来源。它不能自动确定美国目标人群的绝对基线。[kjim.org](https://www.kjim.org/journal/view.php?number=170514\&viewtype=pubreader\&utm_source=chatgpt.com)
- 中国人群研究，报告 BMI 与尿酸的线性、非线性关系，但部分模型调整了多项额外变量，需要核查原表、尺度和调整条件。[Springer Nature Link](https://link.springer.com/article/10.1186/s12967-019-02142-9?utm_source=chatgpt.com)

### 2. Agent 应当展示什么科学决策

一个合理的过程是：

**先处理分布来源。** 提取来源年龄、性别结构与尿酸统计，建立对应来源上下文。

**再处理关联来源。** 检查 BMI 相关统计到底是分层汇总、简单调整系数，还是充分调整系数。

**识别不兼容部分。** 如果缺少额外调整变量的联合信息，就将对应系数列为暂不可数值使用，寻找可重放的统计或补充证据。

**提出低复杂度结构。**

```text
h(尿酸) =
    截距
  + 性别效应
  + 年龄函数
  + BMI 函数
  + 可选分组斜率
  + 残差
```

这里不预填“真实系数”。参数由来源校准得到，未识别部分保留为假设。

### 3. 冻结后分析什么

可以预先安排：

| 分析 | 作用 |
|---|---|
| 调整年龄、性别后的 BMI 关联 | 主要科学关系 |
| 年龄曲线或性别分组曲线 | 同一生成器的复用分析 |
| 分组均值与分位数 | 基本分布保留检查 |
| sex×BMI | 有充分证据时的挑战项 |
| 阈值比例 | 可选探索，重点检查尾部和基线迁移 |

至少一项复用分析不直接作为校准目标。

如果最终来源包不足以支持分组斜率，允许这一项得到“不足以支持”的结果。**完整实例的价值，是展示证据怎样变成生成决定，以及这些决定在真实数据中产生什么结果。**

## 十、怎样设计实验，才能回答你真正关心的问题

我建议把实验分两阶段。

### 第一阶段：完整实例

先完成一个新案例的完整证据链：

1. 输入与允许信息清楚；
2. 文献原文和提取结果清楚；
3. 每条证据的实际用途清楚；
4. 生成结构与假设清楚；
5. 校准、来源检查和真实修改可复查；
6. 冻结后一次性执行预定分析；
7. 成功、失败和不确定结果完整报告。

可以从“两次独立 Agent 构建，每个冻结情景三次残差输出”开始。这些数字是**首轮工程配置建议**，不代表经过功效计算，也不能算成多个独立生物学任务。

### 第二阶段：针对新增机制比较

只有主张某个机制改善结果时，才增加对应比较。

例如：

**主张来源条件处理有效：**

- 使用相同证据；
- 尽量保持模型表达能力相近；
- 保持相近计算预算；
- 对比适用的常规统计校准方法或具体组件消融。

**主张定向补证有效：**

- 先固定基础证据；
- 记录缺口如何被识别；
- 记录新增证据改变了什么；
- 检查目标分析是否改善，以及其他分析是否退化。

需要注意：增加证据以后变好，首先说明新增信息及其使用有价值；若要进一步声称算法更优，仍需要同证据条件下的比较。

### 评价指标应贴近分析用途

建议主要报告：

- 效应大小误差；
- 曲线形状和局部偏差；
- 分层关系误差；
- 关键分布和尾部表现；
- 对假设变化的敏感性；
- 参考真实分析自身的不确定性。

真实效应接近零、参考区间很宽时，不应仅凭符号不同就判断失败。反过来，方向一致但效应被大幅压缩，也不应自动算成功。

## 十一、现有 M10 结果对新设计的启发

既有 M10 很适合用作开发依据。

代码与结果显示，一些主效应可以保留，但分组斜率和曲率更脆弱；部分 HbA1c 的 BMI 作用来自显式假设。因此，来源解释和模型结构需要进一步对应到具体分析，而不能将所有正向结果都解释为文献证据被成功利用。依据见 [MILESTONE_10_RESULTS.md](https://github.com/ziwang11112/evidence-guided-virtual-cohorts-2026/blob/d33d0cbad4c199fe5b450688fe8050d72afd9861/biomedical_research/virtual_cohort_system/MILESTONE_10_RESULTS.md)。

另外，既有选定生成器没有发生实际科学结构修订，所以当前结果还不能证明“自动发现缺口—修订生成器”的机制有效。

这给下一轮一个非常具体的任务：

> 完整记录一次来源失配如何被识别，为什么选择某个动作，动作怎样改变生成器，以及改变是否改善了独立目标分析。

如果没有必要修订，保留原模型同样是合理结果。重点是决策正确、证据充分。

## 十二、我建议现在按这个顺序实施

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| **1** | 独立来源上下文与分析算子 | 来源范围、单位、变换和调整条件可以正确重放 |
| **2** | 校准会话 | 参数试探可复现，不改写冻结对象 |
| **3** | 一个 Agent 的有限动作循环 | 能完成证据解释、候选提出、校准、诊断与停止 |
| **4** | 新案例准入与冻结 | 来源包、任务范围、分析计划在目标揭示前确定 |
| **5** | 完整实例评价 | 同一生成器的多项分析得到统一报告 |
| **6** | 根据结果扩展机制 | 只比较和深化有明确作用的新增能力 |

第一版不需要同时解决高维多组学、完整虚拟人口、复杂缺失机制和多个结局的联合生成。三种用途可以共享系统内核，但应分别建立科学证据。

**我对这个项目最具体的建议是：先把 `SourceContextSpec → AnalysisOperator → CalibrationSession → Frozen Generator` 这条链条做实，再让一个普通 Agent 操作它完成新实例。**

这一步完成后，你们就能清楚回答：系统真正利用了哪些发表信息，哪些生成决定仍来自假设，同一份增补数据能支持什么科学分析，以及下一项方法改进应当发生在哪里。
