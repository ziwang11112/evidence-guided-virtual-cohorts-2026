# Claim-focused experiment expansion after v0.27

Status: design proposal, not a frozen protocol or a launched experiment. Prepared in response to the user's question about the next experiments and whether to add many different cases. It does not reopen old frozen experiments or extend historical acquisition budgets.

## Central question

Can a documented scientific Agent workflow turn a research request and study-qualified published evidence into joint virtual biomedical data that support specified analyses, across materially different tasks?

The principal output is analyzable data. Revision improvement, multiple Agents, new training losses and superiority over every possible statistical model are not required claims. Whole-cohort generation without target participant inputs remains the leading setting. Enrichment, missing-cell completion and longitudinal reconstruction retain their separate information conditions and need not all become new primary experiments.

## Why breadth alone is insufficient

The v0.27 record already covers glycemia, lipids, iron-status analyses and supplied longitudinal-model reconstruction. It includes multiple reference cohorts, different historical controller versions, developmental comparisons and stronger sealed/prospective designs. More seeds or renamed requests do not create new clinical validation. The six descriptive Q1 information contrasts improved in five cases and worsened in one. This motivates testing evidence use across task types, while the dispersion and dependence mismatches motivate explicit analysis-specific evaluation.

The useful expansion is a consistent, documented execution of a small task suite, plus evidence specific to any stronger claim. The old record remains valid under its original version labels; no blanket historical rerun is needed.

## Priority after independent design review

An independent statistical reviewer challenged the value of rerunning four already exposed cases before seeking stronger scientific evidence. That objection is accepted. The recommended next scientific unit is **one prospective intended-use confirmation**, after checking the selected execution version. The existing three-domain results supply breadth already. A four-task uniform-release rerun is an optional capability experiment, not the default next action and not a prerequisite for the confirmation.

For that first confirmation, use five independently authored constructions with three draws each (15 final tables) if the approved resource budget permits. Five is a practical repeatability budget, not a power calculation or a validated reliability threshold. The actual model/context metadata and all failed or retained candidates must be recorded. If a fresh admissible reference is unavailable, stop at the documented development claim; do not automatically replace this unit with 36 old-target outputs.

The next information contrast is optional and should address missing conditional/joint information, not just reproduce the existing five-of-six descriptive improvement. It can be built into the prospective protocol before any reveal if credible extra evidence is already available. If inspired by the first confirmation's revealed results, it requires a different reference for a new confirmation claim. A packet-based developmental diagnostic on old targets is still valid when labeled accordingly.

No formal uncertainty-coverage experiment is required unless inference, power or confidence-interval validity becomes a paper claim. No broad disease sweep is recommended. A shared-data published-method comparison on one or two genuinely compatible tasks is a separate submission-strengthening option, not a universal-superiority requirement.

## Experiment menu and implementation order

The sections below retain the explicit alternative breadth budget for planning, not as an instruction to run all experiments. Recommended order: version/interface check → one prospective confirmation → decide whether a targeted information contrast or a compatible-method comparison fills a remaining claim-critical gap. Existing breadth is first organized and reused under its actual versions.

### 0. Lock an executable version and verify the interface

Specify the actual available author service/model identity and obtainable inference settings, task and retrieval interfaces, evidence/review rules, source-check implementation, output ABI and resource accounting. Record unavailable provider metadata honestly. The protocol must distinguish version and review-budget constants from scientific choices left to the author: search strategy, paper count within resource limits, model family, assumptions and retain/revise decision.

Use at most one already exposed developmental task for a small end-to-end smoke test. Judge dispatch, source registration, isolated sampling, artifact binding and evaluator operation; do not repair the generator to match its known clinical target. If a mechanical defect is repaired, version and record it before the main suite. A smoke test is not an additional successful biomedical case. Prior runs can replace this smoke test if they already verify the exact selected release.

### A. Existing cross-task evidence and optional uniform-release benchmark

Candidate suite, subject to source-admission and permitted-access checks before running:

| Existing task/reference | Scientific reason to include | Proposed analyses and diagnostics |
|---|---|---|
| CHNS glycemia | Joint conditional relationships | Age/sex-adjusted BMI association, conditional glucose association, adjusted age association; marginal and residual variation |
| ENSANUT glycemia | Different population/selection and adjustment response | Age association and BMI association before/after glucose adjustment; dispersion and source-to-target assumptions |
| Turkana lipids | Two biomarkers with joint dependence | BMI–TC and BMI–HDL adjusted associations, residual TC–HDL correlation; component coherence and conditional variability |
| NHANES iron status | Threshold and continuous analyses of the same records | Joint low-marker prevalence, threshold odds ratio and continuous rank correlation; marginal tails and measurement compatibility |

These are four task/reference conditions across three biomedical domains. All are already exposed at project level and remain developmental benchmarks. CHNS and ENSANUT do not become independent biological domains just because their datasets differ. Source overlap must be retained, and each dataset's exact original selection/weighting definitions must be recorded. Task admission must not depend on which known endpoint looks favorable.

Only if uniform current-release coverage is an explicit claim not supported by existing runs, an optional initial budget is three fresh authoring sessions per task and three output seeds per selected law: 4 × 3 × 3 = 36 final tables from 12 independently authored constructions. The authoring sessions are repeated workflow attempts, not independent patient cohorts. With only three authors per task, displays and summaries remain descriptive. Trial/review outputs and any failed attempts count separately and must be retained; this is a final-delivery count, not a total execution-cost claim. This is not the preferred default expansion.

Freeze common workflow and evaluation before this suite. Where an old result has the exact necessary version, information boundary and metadata, reuse it transparently; otherwise run a new, separately named developmental benchmark rather than overwriting history. A large-scale run is not yet authorized by this proposal alone.

### B. A small information contrast if it strengthens the final paper claim

Choose two structurally different tasks, one glycemia and one joint-biomarker task, before the experiment. Compare:

- E0: qualified marginal/population evidence without the designated relationship evidence.
- E1: the same material plus a defined joint or adjusted relationship evidence bundle.

Hold task, author service, workflow, review rules, final row counts and nominal resource budgets fixed. Use fresh contexts without cross-arm artifacts or target results. This contrast tests the role of admitted information, not the benefit of additional Agent roles. A packet-based information contrast and free retrieval are different protocols: unrestricted E0 retrieval could recover its withheld E1 evidence. Either use fixed curated inputs for this contrast, or define and audit a genuinely different retrieval-access intervention and label it accordingly.

Only reuse E1 tables from an optional common-release benchmark when their entire information access and execution protocol match the contrast. If that benchmark uses open retrieval, the default is a separate controlled packet-based comparison, not retrospective relabeling. Three authors × three seeds × two tasks × two arms means 36 final tables; adding only the two E0 arms is 18 tables only when matched E1 reuse was planned and valid. Existing Q1 can remain the primary information contrast if a new one would merely repeat it without testing a missing capability. For a single new case with the five-author confirmation budget, a prospectively combined two-arm contrast would instead be 2 × 5 × 3 = 30 final tables; do not add both budgets automatically.

No new component is justified by this design. Retained candidates and a null/negative information contrast are valid outcomes. No success-only selection of generators, seeds or endpoints.

### C. Preferred next scientific unit: one fresh-reference confirmation

If the paper is to claim usefulness on a new population under the selected release, admit one genuinely new reference before inspecting its target results. Prefer an independently recruited population or distinct study family with compatible measurements and external evidence; a new survey cycle or different indicator is not automatically unexposed. Existing access and exposure records require review. No fresh admissible target is asserted to be ready here.

The analysis question can be given to the Agent. External evidence can include the same kind of relationship being evaluated. Target individual outcomes and reference results remain outside construction/revision for this particular transfer experiment. If those results are intentionally supplied, the experiment instead evaluates reconstruction/calibration and is labeled as such.

Predefine approximately three useful analyses, population/measurement definitions, source/target overlap checks and continuous reporting criteria. The recommended five-author, three-seed configuration produces 15 final tables. Evaluate all selected laws once against the held reference; preserve failures. Source-evidence results cannot substitute for that reference. First inspect the existing access/exposure inventory for a defensible unexposed target; a new indicator in a known cohort is not automatically a new independent target. If a suitable legal reference is unavailable, retain the developmental claim rather than relabeling old targets or expanding data acquisition without a separate plan.

## Quality evaluation tied to the requested use

1. **Primary scientific analyses:** run the same specified regression, adjusted contrast, nonlinear function or joint-threshold calculation on generated and measured data. Report direction, magnitude, adjustment response and reference uncertainty in interpretable units. A direction-only result is narrower than quantitative agreement; generated p-values are not the primary quality criterion.
2. **Necessary explanatory diagnostics:** conditional residual variation, joint dependence, quantiles/tails and physiological/coherence checks relevant to the requested analysis. They explain why an apparently correct coefficient may still support a limited use. Do not pool them into an arbitrary overall quality score.
3. **Uncertainty and evidence units:** separate within-law Monte Carlo variation, between-author/model variability, source-estimation uncertainty and reference-sample uncertainty. More generated rows improve numerical approximation to a law; they do not increase clinical information. Repeated seeds cannot be the statistical replicates for a general workflow-success claim.
4. **Use tolerances:** where an intended-use margin is defensible, obtain a scientific rationale before new target disclosure. On already exposed benchmarks, retain continuous discrepancies or clearly label post hoc thresholds. A biomedical collaborator should assess the scientific consequence, not choose a cutoff that rewards the observed result.
5. **Optional real–real context:** compare real and generated estimates with the same separate reference and the same analysis/sample-size convention, preserving clustering/weighting. Use matched designs and report selection dependence. Do not reuse the earlier asymmetric complementary-sample geometry as a passing threshold. This context measures reference sampling variability, not full source-to-target transfer uncertainty.
6. **Operational evidence:** record retrievals, admitted evidence, source-check availability, actual reviews/repairs, end-to-end elapsed time, separately attributable human/Agent/tool effort, known model metadata and failed outputs. Do not equate numerical-worker runtime with total scientific labor saved.

## Comparisons and figures

A runnable published comparator is useful on one or two tasks where its input assumptions and supported output genuinely overlap. The published paper's score alone is not a head-to-head comparison. Select such a comparison after checking the implementation, input availability and licensing; do not invent an all-purpose manually optimized opponent. Existing fixed statistical comparisons remain bounded evidence under their original protocol.

The main figures should present: (1) task/evidence-to-joint-data workflow and actual review roles; (2) complete cross-task scientific estimates with reference uncertainty and all authors; (3) information-contrast results if retained; (4) one model-choice case connecting evidence/assumptions to successful and unresolved analyses. Source checkability and dispersion/dependence failures belong alongside, not hidden behind marginal-fit scores. A fresh confirmation gets its own panel rather than being pooled with development.

## Stop rules and immediate priority

- Do not add cases simply to increase a success numerator. Stop expanding a missing-evidence task when the required conditional evidence is unavailable under the planned access/resources; report the specific unsupported analysis.
- If a shared interface or operator is defective, fix and re-review it before a new release. If the implementation works but source-to-target assumptions fail, do not tune to the revealed answer or add a new Agent layer by default.
- First finalize the executable version and evaluation sheet. Use the existing task matrix to show breadth without mandatory reruns. Prioritize one fresh confirmation if the stronger claim is retained and a reference is admissible; use any subsequent information contrast only for a distinct scientific question. Do not run the optional breadth budget merely because it is enumerated here.

This plan favors three distinct biological domains, transparent task definitions and a small number of independent constructions over dozens of superficially different datasets. It is a proposal; exact tasks, sources, counts, budgets, model availability and decision criteria still require a single prospective protocol and review before execution.
