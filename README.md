# Evidence-guided virtual cohorts

Private research development repository. This is an explicitly allowlisted export of method documents, reusable code, artificial-fixture tests and aggregate analytical results. It is not a complete copy of the research workspace.

**Current writing checkpoint after C4:** the [draft readiness and core-method freeze checklist](biomedical_research/virtual_cohort_system/docs/DRAFT_READINESS_CHECKLIST_2026-10-31.md) permits provisional drafting now, requires an executable method and case contract to be frozen before new target results, and locks claims only after the complete evaluation. Existing pilots remain development evidence across versions; C3 and C4 do not establish a new real-cohort confirmation. This is a planning update, not a new experiment or completed method freeze.

Start with [the current research direction and paper storyline](biomedical_research/virtual_cohort_system/docs/PAPER_STORYLINE_AND_DIRECTION_2026-10-31.md): **turn published biomedical evidence into reusable virtual data for scientific analysis**. Evidence-only complete virtual-cohort generation is a core intended capability: no individual-level records are required as an input, although published evidence and a target-population specification are still needed. Whole-column augmentation and partial-cell completion are separate information regimes within the same method. Their scientific usefulness must be validated separately.

The latest completed scientific unit, [M17-B](biomedical_research/virtual_cohort_system/MILESTONE_17B_RESULTS.md), tests complete virtual cohorts with **zero individual records supplied to the builders**. Two fresh Agents used three external publications to author generators for all four substantive variables. Six seeded 320-row draws were evaluated against a newly admitted measured quota cohort. All six preserved adjusted BMI, age and sex directions; magnitudes were mixed and all generated BMI means were below this measured reference-sample mean; this does not establish bias against an unknown population mean. See the [reference-interpretation clarification](biomedical_research/virtual_cohort_system/docs/M17B_REFERENCE_INTERPRETATION.md). Both Agents retained their initial models, so twelve scheduled initial/final entries represent six unique tables and no repair gain. All eight analyses are reported. Independent recomputation matched 1,482 fields; a raw audit route-label warning is preserved and separately adjudicated. This is selected analytical feasibility, not general data equivalence, national-population inference or method superiority. See the [protocol](biomedical_research/virtual_cohort_system/docs/M17B_WHOLE_COHORT_PROTOCOL.md), [independent audit](biomedical_research/virtual_cohort_system/reports/m17b_whole_cohort_2026-10-31/independent_audit/FINAL_AUDIT.md), and [bounded export record](docs/M17B_EXPORT_2026-10-31.md). The revealed reference is closed to tuning.

## Run the independent checks

The export preserves the `biomedical_research/` package tree. Use Python 3.12 and a compatible installation of numpy, pandas, scipy and statsmodels. Exact versions used by the original batch are recorded in its `results/summary.json`; this export does not vendor an environment.

From the repository root:

```shell
python -B -m unittest discover -s biomedical_research/population_framework/tests -v
python -B -m unittest discover -s biomedical_research/evidence_virtual_cohort_framework_2026-10-27/development_batch/attempt_02 -p test_batch.py -v
python -B biomedical_research/evidence_virtual_cohort_framework_2026-10-27/stage1/test_stage1.py
python -B biomedical_research/evidence_virtual_cohort_framework_2026-10-27/stage1/test_reporting.py
python -B sync/audit_export.py
```

The fixture tests require no study data. The full batch and original independent audit require omitted local artifacts. Do not interpret archived original `run_batch.py verify` instructions as a claim that this public-data-free checkout can replay the clinical study. See [reproduction and local data](docs/REPRODUCTION.md).

## Synchronization

`sync/sync_export.py` copies only exact entries in `sync/source_allowlist.json`. It never discovers new research files, uploads files or pushes Git. Changes to the allowlist require content review. A local refresh is:

```shell
python -B sync/sync_export.py --workspace PATH_TO_LOCAL_RESEARCH_WORKSPACE
python -B sync/audit_export.py
```

For a bounded refresh, repeat `--only-source` with each exact allowlisted source path. Unselected export files and manifest records must remain unchanged. Frozen metadata retains original source hashes; the export manifest records any reviewed path normalization.

Review `sync/EXPORT_AUDIT.json` and the complete `sync/FILE_INVENTORY.tsv` before an explicit Git commit/push. This repository should remain private. The repository's remote access control must be checked separately; the scripts do not change GitHub visibility.
