## Reconstruction boundary

The curated mapping is `virtual_cohort_system/work/c3s/` to `virtual_cohort_system/reports/c3s/`. This checkout is a reviewed research record, not a complete runnable copy of the local workspace. To reconstruct the original relative layout in a separate working copy, the C3 record must occupy `virtual_cohort_system/work/c3s/`; the existing prior-cycle bridge and artificial metadata fixture must occupy `virtual_cohort_system/work/autonomous_research_cycle2_2026-10-31/method/`. Their exported copies live under the corresponding `reports/` directory. The adapter intentionally retains its original `work/` bridge path and the test source retains the fixture dependency. Source bytes are not patched to make an incomplete export appear runnable.

Original candidate, registry and release commitments remain independently checkable for included files. Engine/runtime digests in releases identify the original execution environment; this checkpoint neither replaces the historical harness nor certifies that the current selective checkout reconstructs that full environment. The controller also requires the separately maintained bundle-global calibration budget. No budget ledger, calibration session, execution tree or run result is included at this checkpoint. Existing scientific release records are historical authorizations for the original bounded sessions, not permission to reset budgets or rerun them.

Excluded payloads include STATE/history, individual-level real or fictional rows, generated tables, raw downloads, full articles/PDF/XML, execution directories, calibration sessions/results, mutable budget ledgers, caches, secrets and builder CLI logs. Only short authored source summaries are included. Completed aggregate results, selected recipes and figures require a separate later export release and manifest.
