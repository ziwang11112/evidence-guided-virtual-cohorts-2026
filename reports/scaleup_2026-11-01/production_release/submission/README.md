# Wave A submission packaging

This additive wrapper finishes candidate packaging around the reviewed assembler, lifecycle, bridge and campaign ledger. It supplies no Agent scientific law, parameter values or approval. It never imports submitted code or executes a generator. The only pre-freeze program check is AST syntax and the three-positional-argument interface. The twelve new invented tests exercise packaging/review boundaries; actual clinical fitting/generation remains separate.

The twelve inputs are the retained short workspace `evcA/K01|K02/A01..A05|S01` bundles. Both their assembly receipts and registered byte commitments are checked. `previews/` contains ten selected-input Agent packets with exact allowlists and unassigned placeholder actor IDs. These are explicitly previews, outside constructor output folders, not dispatched work. `PROMPT_PREVIEW_INDEX.json` records them. There is no S01 Agent prompt. Do not send an old project README, full bundle tree, other constructor, prior result, ledger tree or statistical-reference law to an Agent.

## Practical sequence

1. The root creates and independently reviews the actual global release with this `submission.py` included among its code artifacts and a verified runtime providing numpy, pandas and scipy. Root opens the single ledger and calls `begin_construction(case, constructor, actual_actor_id)` before delivering scientific work. Actor ID is exactly ledger construction_id, not an unbound label. A fresh Agent receives no inherited project/results context.
2. Call `render_agent_packet(bundle, actor_id, "initial", new_packet_directory, ledger_path=ledger)`. It verifies release/actor and writes only selected input copies, `AGENT_PROMPT.md`, and `ALLOWLIST.json`. Deliver that prompt and those listed files. The Agent writes exactly generator.py, model_spec.json, decision.md, checks.json and context_authoring.json in its separate submission directory. The prompt is self-contained on schema, libraries, whole-cohort mode, context eligibility, scientific freedom, inline derivation and forbidden calibration/target inputs.
3. Call `prepare_submission(bundle, submission_directory, actor_id, stage, ledger, derivation_mode="fixed_parameters"|"inline_deterministic", revision=None|revision_object)`. It validates the five files, mechanically copies fixed evidence, builds the exact bridge plan, and creates unsigned `candidates/initial` or `candidates/final`. Scientific parameter values are not changed. JSON is encoded canonically for this interface; original authored file hashes remain in `submission_binding.json`. Checks must truthfully remain not-computable with no pre-freeze result artifacts. The packager does not manufacture a numerical check.
4. Inspect `review_requests(bundle, stage)`. An actual independent reviewer reviews the unsigned payload, actor/source bindings and full scientific specification. Supply a `submission_review` committing its submission_sha256; K01 also requires a separate `k01_declaration_review` committing k01_declaration_sha256. Both must name the actual actor as producer and a distinct reviewer. Use the existing decision/independent/reviewer_id/producer_id/reviewed_utc/reason/approved_sha256 schema. No helper fills an approval or reviewer ID.
5. Call `freeze_prepared(bundle, stage, ledger, submission_review, k01_declaration_review=...)`. It rechecks payload/input integrity and ledger authorization, installs the supplied reviews, freezes the lifecycle candidate, then invokes bridge.prepare. Review the returned derived child binding requests independently; call `seal_prepared(bundle, stage, ledger, actual_bridge_reviews)`. This seals the bridge and binds the stage to the ledger without dispatching it.
6. Root continues with the existing `ledger.begin_bridge`, guarded `case_execution.execute_case_stage`, source collectors, `ledger.finish_bridge`, and one `ledger.deliver_source_feedback`. Never call an unguarded source collector as an alternative execution path. A failed slot remains consumed; retained finals alias initials. No target outputs or logs enter the builder packet.

After delivery and **before any final decision**, call `render_feedback_packet(bundle, actor_id, new_decision_directory, ledger)`. It requires completed/delivered initial feedback and decision=None. The same Agent receives only source receipts, its own initial files and the admitted metadata and returns `{decision:"retain"|"revise"|"stop",reason:...}`. This step neither assumes revision nor mutates the ledger. Root must not select revise on the Agent's behalf just to expose feedback.

Only the actual Agent choice recorded by `ledger.decide_final(...,"revise",reason)` authorizes a changed Agent final. Rendering the final packet reverifies the delivered source-only inventory and copies those report bytes under local `source_feedback/` filenames, plus the same actor's initial five files. It does not expose ledger/report parent paths or target files as allowlisted inputs. The final candidate binds the exact delivered packet hash and copied reports in checks artifacts, and lifecycle-freezes with the initial parent and a truthful revision object `{reason,kind:"revise",addressed_findings,remaining_limitations}`. S01 cannot revise. A retain decision uses the existing ledger alias path and creates no new candidate/output.

Unsigned candidates are exclusive stage paths. Invalid syntax/schema is rejected before writing; once a valid draft is prepared, any change invalidates its review digest. This wrapper does not silently overwrite or repair a prepared candidate, resume a partial seal, generate retries, or manufacture scientific review. Resolve a pre-freeze review rejection explicitly with the actor before a new reviewed commitment. Hash/ledger checks are procedural retained-byte controls, not an LLM filesystem sandbox or hostile-host authentication.

## S01 inline path

After actual release/construction authorization, call `prepare_s01_authoring(bundle, actor_id, ledger, new_submission_directory)`, then use the same prepare/review/freeze/seal flow with derivation_mode="inline_deterministic". The wrapper copies the **exact committed reference module bytes** as a prefix, leaving its docstring and future import intact, and appends one small generate function. That function evaluates `fit_reference(normalized_source_constraints)` and passes its `parameters` to sample inside the existing isolated execution. No helper project file is needed inside the worker. Source operands come from the reviewed K01 reference-input view or K02 compiled normalized constraints. Their evidence IDs alone enter operand provenance; contexts use the precommitted reference assumption. Packaging never calls either fit_reference or sample.

The S01 source and law are controller/reference-only and are never in an Agent packet. The reference retains its precommitted law irrespective of finite source mismatch when execution integrity is valid. There are zero separate analytic jobs and no replacement optimizer/calibration. The actual five-slot invented smoke reported SciPy missing in the older venv; those failures remain recorded. Root subsequently repaired the dependency with SciPy1.16.3, and the independent reviewer reported one actual isolated betainc/inverse probe passing. Release must bind that verified runtime; this packaging unit did not execute the smoke, fit actual source values or change the statistical law.

## CLI

`python submission.py ACTION --bundle BUNDLE ...` supports `preview`, `prompt`, `feedback`, `s01`, `prepare`, `requests`, `freeze`, and `seal`. Use `--actor`, `--stage initial|final`, `--output`, `--submission`, `--ledger`, `--derivation-mode`, `--revision` (JSON), and `--reviews` as appropriate. `feedback` renders the decision-only packet before decide_final. Freeze review JSON is `{submission_review: ..., k01_declaration_review: ...}`; omit the K01 field for K02. Seal review JSON is the existing bridge's context-keyed binding/supplement/proxy review packet. CLI operations return concrete review requests or receipts; none dispatches scientific code or sends messages to an Agent.

Production artifacts are source, tests, this README, preview index, preview packets, and verification/review results. `.test_tmp/` is invented test material, not a constructor packet or publication allowlist. No old code, STATE, scientific commitment, input bundle or export was edited by this unit.
